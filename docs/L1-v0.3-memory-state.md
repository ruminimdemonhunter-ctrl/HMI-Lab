# Level 1 v0.3 local memory-state format

Status: format version 1, implemented by `src/level1/l1_state.c`.

## Boundary and purpose

This file preserves validated Level 1 behavior memory across process restarts.
It is a local, explicitly configured file, not an update service. Loading always
returns the core to `HOLD`; transient candidates, counters, timestamps, and
actions are deliberately not restored. The monotonic adaptation window restarts,
so a process restart cannot accelerate adaptation.

CRC32 detects accidental truncation or corruption. It is not a MAC or digital
signature and provides no authenticity against an attacker who can rewrite the
file. A future L2 must use a separately reviewed authenticated authorization
boundary before it can supply state.

## Canonical encoding

All multibyte integers are unsigned little-endian. The file is exactly 64 bytes.
Unknown versions, wrong sizes, trailing bytes, nonzero reserved bytes, invalid
policies, invalid rollback ordering, or a CRC mismatch are rejected.

| Offset | Size | Field |
|---:|---:|---|
| 0 | 8 | Magic `HMIL1S1\0` |
| 8 | 4 | Format version (`1`) |
| 12 | 4 | Total size (`64`) |
| 16 | 4 | Active policy schema version |
| 20 | 4 | Active policy generation |
| 24 | 2 | CPU trigger, basis points |
| 26 | 2 | Memory trigger, basis points |
| 28 | 2 | I/O trigger, basis points |
| 30 | 1 | Confirmation samples |
| 31 | 1 | Bounded adaptive debounce increment (`0..2`) |
| 32 | 1 | Previous-policy-present flag (`0` or `1`) |
| 33 | 3 | Reserved, zero |
| 36 | 15 | Previous policy in the same field order as offsets 16..30 |
| 51 | 9 | Reserved, zero |
| 60 | 4 | IEEE CRC32 over bytes 0..59 |

Generation zero is accepted only when every policy value equals the compiled
default. A previous generation must be strictly lower than the active one.
Every non-default policy must pass the same compiled safety envelope used for
live proposals.

## Atomic persistence and recovery

`l1_state_save_atomic()` creates a mode-0600 temporary file in the target
directory, writes exactly 64 bytes, calls `fsync()` on the file, closes it,
renames it over the target, then calls `fsync()` on the parent directory. Under
the documented single-writer model, readers see either the previous complete
state or the replacement. A filesystem or platform that does not provide the
required rename/fsync guarantees is outside this result.

`l1_state_load()` initializes compiled defaults before attempting any read. Any
failure therefore leaves generation zero, `HOLD`, no rollback snapshot,
`debounce_extra=0`, and a fresh time gate. The monitor continues safely and
reports the error.

Concurrent writers, network filesystems, disk exhaustion after rename, hostile
directory owners, and power-loss behavior of the underlying storage stack are
not proven by the unit test. The state path should remain under the unprivileged
`lab` user's private directory and outside the disposable synchronized source.
