# HMI Level 1 v0.8 recorder-efficiency validation

## Outcomes

```text
RECORDER_EFFICIENCY: GO
REAL_EVIDENCE: INSUFFICIENT
DIAGNOSTICS: NO_GO
SHADOW_PREDICTION: NO_GO
ACTION_COUPLING: NO_GO
```

The optimized recorder met every frozen V0.8 efficiency and correctness gate.
Its primary 180-sample deterministic end-to-end median was **22,700 process CPU
ns/valid sample** against the preregistered 1,000,000 ns/sample limit. Median
RSS was **1,476 KiB**, and the maximum of the five runs was 1,628 KiB, below
the 8,192 KiB limit. Baseline and candidate traces had identical rows and
checksums at all three frozen sample counts.

No research-length real PSI recording was authorized or created. The permitted
live evidence consists only of bounded two- and five-sample integration and
performance smokes, all shorter than the 60-second forecast horizon. There are
zero evaluable real forecast windows versus the frozen minimum of 30, so real
evidence is explicitly `INSUFFICIENT`.

Recorder efficiency is not prediction quality or workload benefit. It does not
revise the V0.7 `DIAGNOSTICS_NO_GO`, the V0.6 shadow prediction and action
coupling NO-GO decisions, or the V0.4/V0.5 negative findings. It authorizes no
resource actuation.

## Provenance and implementation

- Base: merged V0.7 commit `441c3053c11f2fb30711a6da1f655dad0f51f364`.
- Frozen V0.8 protocol: `0aef3c1`.
- Pre-report implementation: `b66eaec`.
- Guest: Debian Linux `6.12.113+deb13-amd64`, x86_64.
- Compiler: GCC 14.2.0.
- Implementation: three `O_RDONLY|O_CLOEXEC` PSI descriptors, one bounded
  1,024-byte stack buffer per `pread()`, and the unchanged PSI value parser.
- No dynamic allocation was added to the recorder loop, L1 decision path, or
  shadow path.

The production recorder now reports process CPU at phase boundaries:

1. setup: CLI/path validation, output/source open, and headers;
2. loop: clocks, all three reads/parses, encoding, hashing, writes, and sleep
   syscalls (sleep wall time is not process CPU);
3. publication: source close, footer, flush, `fsync`, close, hard-link
   no-replace publication, and temporary-name removal; and
4. total plus monotonic wall time and process peak RSS.

The prior one-shot adapter remains available as the benchmark comparator. The
monitor and all decision code remain unchanged.

baseline/candidate order. Each process created bounded private synthetic PSI
fixtures and a V1 trace in `/tmp`, exercised encoding, hashing, file `fsync`,

read or retain real PSI and did not sleep.

Five optimized five-sample live captures reported:

- complete process median 373,800 ns/sample, range 364,800..444,400;

An initial persistent-`stdio` implementation was rejected during development:
buffering retained stale fixture values after external updates, while disabling
buffering made the 65-row smoke slower than baseline. The final bounded
descriptor/`pread()` implementation corrected the equivalence defect without
adding another optimization candidate or changing the frozen measurement
population. This discrepancy is retained rather than hidden.

## Safety and limitations

- The optimized benchmark uses regular-file synthetic PSI fixtures; the
  separate live source profile covers procfs read/parse behavior without an
  end-to-end long real recording.
- Five repetitions characterize this Debian QEMU environment, compiler, kernel,
  page cache, filesystem, and host-load interval; they do not establish a
  universal performance bound.
- `getrusage` has finite resolution, and setup/publication `fsync` cost varies.
- PSI is an observational stall proxy, not a causal measurement of performance
  benefit or a resource-control outcome.
- FNV-1a is corruption detection, not authentication.
- No real forecast accuracy, calibration transfer, workload benefit, energy
  saving, counterfactual action, or actuator was evaluated in V0.8.

Git/source review found no raw recording, compiled binary, credential, VM
image, backup, network/upload path, PSI trigger write, L2/L3 component,
scheduler/cgroup control, kernel/device/firmware modification, privileged hook,
or hardware-control interface.

## Post-review baseline compatibility correction

This section records a correction made after the frozen evaluation and the
measurements above. It does not replace the frozen protocol, measurements,
checksums, or conclusions.

Review of commit `9ff5ce894318169fc03ccf090eb0be51c8be2b2a` against the merged
V0.7 source found two unintended changes in the retained one-shot comparator:

- the refactored reader required every `fgets()` result to end in a newline,
  whereas V0.7 accepted a syntactically complete final line at EOF; and
- it changed a successful parse to failure if `fclose()` reported an error,
  whereas V0.7 ignored the `fclose()` result.

The comparator now restores the historical V0.7 read loop and close behavior.
Regression fixtures prove that it accepts complete final lines without a
newline and rejects missing totals, missing total values, trailing garbage,
cross-line field borrowing, empty input, and oversized input as applicable.

The persistent production reader remains intentionally stricter than the
historical comparator at the file-format boundary. It accepts only bounded,
newline-terminated records, as supplied by Linux PSI procfs. Each located line
is now NUL-terminated before parsing; this additionally prevents a missing
field on one record from being found on a later record. For supported
newline-terminated PSI input, deterministic fixtures covering ordinary values,
zero, 100 percent, and `UINT64_MAX` prove value equivalence. A complete final
line without a newline is accepted only by the compatibility comparator and is
not treated as supported procfs input.

same Debian QEMU guest produced the following process CPU ns/sample medians
(nearest-rank p95):
