# HMI L2 V0.2a — Utility evaluation instrument architecture (offline preflight)

**DOCS ONLY AT DESIGN STAGE.** Frozen source of preflight requirements: `docs/L2-v0.2a-preflight-protocol.md` first commit `7efca7267377ff242f4bdc1de0319b10987e4b61`. Parent merged V0.2 research blueprint `d9d06fbbc8fa7e005bdb8cdc5deb8c03ae932f14`; track [issue #39](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/39). This is a **test harness of scientific measurement**, not a new OS identity algorithm or a formal heldout study.

## Why this preflight

Previous HMI studies showed that experimental gates can be invalidated by post-fault eligible counts, actual memory resets/support, miswired candidate-K thresholds, unverified lock hashes, and superficial truth comparisons. Our accepted V0.1 L2 engine has passed engineering, but measuring whether memory helps requires an instrument that catches every one of those classes *before* committing a study.

Preflight advances science-integrity, not learning capability. This phase does not run scientific heldout, generate V0.2 full study truth, or alter actual L2 model bytes.

Every candidate receives a separately initialized *identical history excerpt* and the same contextual/quality/safety inputs. Only the independent scorer can read future truth. The lock verifier gets source/data manifests but is not allowed to use a study heldout path during preflight.

## Component I — Input/truth segregation

- Future truth lives in a separate file with strict schema. Its contents, task labels, confidence/ambiguity and safety conditions are never passed to candidate process arguments, environment variables, model input structures, CLI stdout or fixture filenames provided to candidates.
- Each candidate has a source-provenance statement, permitted training split and per-episode query time; no future data leakage via sorting, partial episode reuse or "peek at next activity" event.
- Explicit labels for `DETERMINATE`, `AMBIGUOUS` and `DENY|RESOURCE_PRESSURE|INVALID_SOURCE` are exclusive truth/scorer metadata; runtime observers see only appropriate coarse safety source conditions.
- Use a simulated two-world twin in which inputs are identical but hidden future outcomes differ. A candidate cannot legitimately satisfy both; this is deliberate and helps detect hidden-truth leakage or implausible personalization claims.

## Component II — Actual support / eligibility

- Use frozen `L2State` source unmodified as an observer. For each query, recompute V0.1 context freshness, post-reset completed sessions >=3, accepted transitions >=6, matching triple support>=2, and explicit safety pressure/invalidity.
- A **separate** Python stdlib or independent pure C11 simulator checks accepted session boundaries, quality, time, duplicate/invalid event and expected support without reading L2's counters as the ground truth.
- A late reset with 2 post-reset sessions MUST be unsupported even if >3 occurred before reset. A nominal 40-row segment with invalid events must not claim 40 eligible rows. Attempted broken readings are known-negative fixtures.
- No outcome is validated by simply comparing two values produced by the **same** model function. Enforce independent code paths and failing mutations.

## Component III — Baselines and calibrated selection

- **Baseline algorithm IDs**: `RECENT_N` with N in {1,2,3,5,8}, `STATIC_WORKSPACE`, `STATIC_GLOBAL`, `ALWAYS_NONE`. V0.1 frozen runs as the candidate under test but is not automatically treated as strongest reference.
- A toy baseline implementation is acceptable if its scripted predictions are clearly labeled `CANNED_PRELIMINARY` and never used to claim full baseline engineering. A fully executable baseline checker must demonstrate actual session truncation/tie-breaking and support/guard masking, not just accept asserted output names.
- The scorer computes toy loss independent of baseline implementation, and the best comparator is selected from *all* permitted baseline IDs by min loss, then safety errors, coverage and deterministic ID tie break. Fixture controls must explicitly make RECENT_N, STATIC_WORKSPACE and ALWAYS_NONE the winners in separate tests.
- Do not conflate a standalone toy selection pass with scientific calibration in real V0.2. The later study needs its own complete baseline fit and selection based on actual calibration, frozen parameters and file hashes.

## Component IV — Independent toy scorer

- Parse predictions and truth using strict bounded ASCII grammar and exact joins; one score per episode and candidate, not per CSV row. Check exact role triples, count wrong positions and abstentions, and distinguish ambiguous task from unknown/corrupted truth.
- Simple **preflight-only** loss: 2 per mismatched role, 1 for NONE on determinate safe, 0 for NONE on ambiguous, 2 for CANDIDATE on ambiguous and 3 for wrong BLOCKED on safe. Candidate on forbidden guard is fatal, never averaged away.
- Before any score, enforce that prediction's pre-query input identity is identical across candidates and available permitted evidence is matched. A mismatch invalidates the case.
- Run separate positive and negative known answers for all arithmetic branches; injected wrong B prediction must cause mismatch relative to its independent expected label, not be accepted because the prediction has valid syntax.

## Component V — SHA256 and first-open order

- Bind exact allowed bytes and selected toy calibration outputs. Do not use a lock that merely contains nonempty-looking checksum strings. Detect changed source, changed training or truth, selected-grid tampering, missing/duplicate/unknown keys, malformed format, and data/manifest identity drift.
- Require `verify_lock()` to complete **before** any open of dummy heldout sentinel path. Use an instrumented opener/logger and assert `open_attempts=0` for every invalid test.
- A valid toy lock can demonstrate that a dummy sentinel opens, but it must never open or score actual future V0.2 study heldout. SHA alone is integrity, **not** signature, authorization, or anti-replay proof.

No accepted V0.1 model edits, no new system daemon or sensor. If any helper uses C11, build under strict normal/NDEBUG/ASan/UBSan/leak and fixed state limits. Python stdlib is fine for offline science tooling but NOT an embedded OS intelligence dependency.

## Independent verification and stop conditions

Preflight PASS **only** if:
- actual V0.1 observer and independent reference agree on post-reset support and negative fault controls;
- hidden truth controls verify non-identifiability, not invented oracle insight;
- all canonical toy scoring cases and unsafe-candidate hard stops pass;
- strongest comparator is selected correctly from *the full frozen grid*, including the case where recency beats static alternatives;
- mutations to file/lock/calibration selections are rejected before any heldout open;
- all L1 core/shadow/priority/source and accepted V0.1 byte identities remain unchanged; normal/NDEBUG/sanitizer/full RC0 and isolated Debian QEMU qualification pass within preregistered resource constraints.
If mandatory tests cannot run, report `NOT_RUN` rather than `PASS`. Do not repair this version's frozen fixtures after exposure. Keep failed harness attempts in the validation report.

## Separation from future V0.2 main scientific study

V0.2a PASS establishes **evaluation tooling readiness only**. A future **separately approved preregistered** V0.2 study must independently freeze exact simulator probabilities, independent episode count minima, train/calibration/heldout seeds, context truth/cost semantics, all comparator grids, sample-dependence assumptions, statistical gates and actual utility losses *before* production of data. It then must freeze corpus SHA identities, calibrate, lock and perform exactly authorized heldout scoring. V0.2a toy known answers must not be mistaken for genuine learner performance.
