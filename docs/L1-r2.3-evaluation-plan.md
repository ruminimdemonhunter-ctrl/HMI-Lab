## 1. Scope and hypothesis

Can an operational-memory histogram acquired from **training-only synthetic machine-pressure history** identify genuinely unusual *engineered* pressure episodes better than a fair, strong, per-machine calibration-tuned **no-memory** detector, without increasing false alarms or influencing protected L1 actions?

R2.3 measures **information utility** on synthetic, independent labeled *episodes*; it does not implement a machine personality, user profiling, app/workflow intelligence, native real-device sensing, OS action, energy saving, or claims of natural-world anomaly accuracy.

Separate engineering correctness from (a) utility against a strong fixed baseline and (b) appropriately individualized responses. The latter must have *independent machine-conditioned truth labels*; different histograms or alerts alone are not acceptable evidence.

## 3. Frozen novelty algorithm (C11 integer-only, read-only)

Build two `L1OperationalMemory` training references by replaying A/B *training CSVs only* with their exact externally supplied `quality`, `valid`, PSI values and monotonic milliseconds, obeying all R2.2 admission, reset, decay and support rules. Do not train using scoring labels. At the end of each training split, export a copied immutable `L1OperationalMemorySummary` (and hash its 80-byte checkpoint for reproducibility). If a training model is not `SUPPORTED`, abstain on its entire calibration and held-out evaluations; no GO.

**During calibration and held-out inference do not update training memory**, even from unscored context rows or after predicting an episode. Treat the training-only histogram summary as frozen. R2.3 is an evaluation of memory-conditioned *recognition*, not a new online learning rule. For drift/change-of-regime recovery, reserve separate exploratory tests; no claiming live continuous adaptation from this scorer.

For each eligible sample and channel c in {CPU, memory, I/O}: determine the exact R2.2 fixed 8-bin index b via its committed quantizer; compute `n_c = sum(histogram[c][0..7])`, `k_c = histogram[c][b]`. Require 1 <= n_c <= 1024 for all channels. Define the integer rarity score:

    score_c = floor(1024 * (n_c + 8 - (k_c + 1)) / (n_c + 8))
    novelty_score = max(score_CPU, score_MEMORY, score_IO)

All intermediate products use unsigned 32-bit or wider arithmetic. `novelty_score` is a bounded **rarity index** (0..1023), **not** a probability of a fault or calibrated AI confidence. The smoothing `+1` per bin and denominator `n+8` are fixed. On `quality != OK`, invalid numeric range/valid flag, missing/small support, or inconsistent bins, emit `UNKNOWN`/abstain, never a negative `EXPECTED`. Never mutate the summary, operational memory, `L1Core`, `L1Shadow`, policy, R2.1 classification or a system interface.

Candidate **single global learner threshold** set, sorted ascending, fixed now:

    {256, 384, 512, 640, 704, 768, 832, 896, 928, 960, 976, 992, 1008, 1016, 1024}

At row level `SUSPECTED` iff `novelty_score >= chosen_threshold`, else `EXPECTED`. Threshold 1024 is a permitted all-negative fallback. At episode level report `SUSPECTED` if **>=5 eligible rows** meet the row threshold; otherwise `EXPECTED`, if the episode has >=10 eligible rows. If insufficient eligible rows or reference unsupported, report `UNKNOWN` and do not score as a negative. Count all abstentions, including those on positive episodes. No future policy coupling.

## 4. Eligibility, episode units, and scoring

Use the frozen `<machine>_<split>_episodes.csv` tables as the **unit of statistical evaluation** (not adjacent correlated rows). Parse using strict bounded CSV/uint validation; reconcile every episode to same `session_id`, `episode_id`, row range and `scoring_class` in CSV. Exclude only rows where `quality` is not `OK`, `valid` false, a PSI field outside 0..10000, malformed time/identity, or existing `exclude_reason` nonempty. A candidate with time regression must not be presented as valid. An episode must have >=10 eligible rows to be scoreable; otherwise explicit `UNKNOWN`. Do not silently exclude any event family or row, and report removed counts by cause.

Score two categories only: `normal` and `positive`. All `context/unscored_transition` rows are ignored as events; for inference, the training model is frozen and they cannot alter it. The episode's frozen engineered class determines TP/FN/TN/FP; false reassurance (EXPECTED on a positive episode) and invalid/no-score coverage must be shown separately. Event family and timing are *not* inputs to the candidate detector.

Metric definitions by machine, plus family and aggregate: `false_alert_rate = FP/(FP+TN)` on **scoreable normal** episodes; `sensitivity = TP/(TP+FN)` on **scoreable positive** episodes; also show total true labels, coverage, abstained positives, exclusion counts, FP/FN, and optional worst-case rates. An abstention may never be claimed as TN; if abstention makes coverage differ materially, primary relative superiority is **UNDETERMINED** unless both systems were compared on common eligible episodes and all abstentions are reported. Require each machine >=20 independent scoreable positive **and** >=20 scoreable normal episodes on held-out; otherwise `R2_UTILITY: INSUFFICIENT_SUPPORT`.

## 5. Fair comparator preregistration and calibration-only selection

Three distinct references:
1. **Integrity baseline:** always `UNKNOWN`, never a superiority comparator.
2. **Previously frozen static comparator:** immutable `r23_fixed_comparator_v1.json`: CPU>=6000bp or memory>=400bp or IO>=2000bp, episode positive when >=5 eligible row hits (>=10 valid rows). Report it, **do not tune or edit its file**.
3. **Strong per-machine tuned no-memory fixed comparator**: independently choose fixed thresholds on each machine's 8 calibration sessions *only* using full fixed grid:

    CPU bp = {1000, 2000, 3000, 4500, 6000, 8000}
    memory bp = {25, 50, 100, 200, 400, 800}
    I/O bp = {250, 500, 1000, 2000, 3000, 5000}
    episode >= row-hit K = {1, 3, 5, 8, 12}, min eligible rows=10

This is 6×6×6×5=1080 candidates **per machine**. Each row hit means *any of the three PSI inputs equals or exceeds its threshold*, as in the frozen comparator. Strong tuning intentionally makes the fixed baseline competitive and permits per-machine parameter differences from calibration; this makes learner-superiority claims conservative. Evaluation is performed on the same eligible observations and episode labels as the learner.

**Calibration objective / deterministic tie order**, fixed before running calibration:
- Constrain calibration false-alert rate <=10% **per machine**; a baseline candidate with zero scoreable normal episodes is invalid.
- Within feasible candidates, maximize positive-episode sensitivity; then minimize false-alert rate; then choose lexicographically smallest `(CPU threshold, memory threshold, I/O threshold, K)` numeric tuple.
- If no candidate meets the cap, select the minimum false-alert rate, then highest sensitivity, then lexicographically smallest tuple, and record `CALIBRATION_CAP_NOT_MET`; this makes the primary utility GO impossible.
- Do **not** rank or adjust candidates using held-out labels, shared probes or fairness on heldout.

**Learned novelty threshold** is **one global integer** for A and B selected over pooled calibration only:
- Feasible iff calibration false-alert rate <=10% **on each machine** and there are at least 10 scoreable normal and 10 scoreable positive episodes per machine. If no feasible criterion exists, choose 1024, mark `CALIBRATION_CAP_NOT_MET`, and forbid GO.
- From feasible candidates maximize `min(sensitivity_A,sensitivity_B)`; then maximize `sensitivity_A+sensitivity_B`; then minimize `max(FPR_A,FPR_B)`; then minimize `FPR_A+FPR_B`; then choose the **largest** candidate threshold (conservative deterministic tie).
- Do not choose a separate machine-specific novelty threshold: machine-specific results should primarily come from **different histories**, not handcrafted per-owner threshold tweaks.

Do **not** use an obviously weak original comparator as the only hurdle. For each machine the **strongest comparator** for GO is whichever of the fixed predeclared and tuned static models yields higher calibration sensitivity at <=10% calibration FPR (tie: lower FPR, then fixed model), locked before heldout. The tuned comparator must always be separately reported even when the previously fixed comparator wins the calibration selection. If fixed calibration FPR exceeds cap, it is not eligible as the 'strongest' at the cap, though still reported descriptively.

## 6. Held-out GO/NO_GO and scientific limits

After calibration lock, use exactly eight held-out sessions per machine (A and B separately) and no training updates. Criteria are conjunctive:
- Valid identical frozen dataset IDs/hashes, scorer source identities, fixed model inputs, calibration parameter lock, no heldout tuning; otherwise `R2_STUDY: INVALID`.
- Both machines meet minimum independent scoreable normal/positive episode counts after exclusions, with no obscured abstention; otherwise `R2_UTILITY: INSUFFICIENT_SUPPORT`.
- For **each** machine, the memory-conditioned detector has held-out FPR **no greater** than strongest locked fixed comparator and sensitivity **no lower** than that comparator.
- At least **one preregistered anomaly family** must have >=5 independent positive held-out episodes **within at least one machine**, and the learned detector must have strictly more true positives than the same strongest fixed comparator on that family; otherwise no utility GO. Report all family counts, including those with <5 episodes, without post-hoc merging.
- Failure of any comparison: `R2_UTILITY: NO_GO`; missing support, external validation or inconsistent coverage: `INSUFFICIENT_SUPPORT` or `UNDETERMINED` as appropriate; never relax requirements after results. Even utility GO is **synthetic** and does not establish real-workload transfer.

## 7. Individuality and probe validity gate

R2.2 memories A/B are known to differ after synthetic train/calibration. This alone does **not** meet individuality. Parent R2.0 requires at least **two preregistered shared-probe scenarios** where *different* novelty decisions are correct for machine-conditioned independent reference labels, plus neutral/fault probes where safe output matches, determinism/restart and adaptive regime-change handling.

**Known limitation of frozen corpus V1:** `shared_probe.csv` has a single `truth_label` per row, not independently supplied A-conditioned vs B-conditioned truth. Consequently, A/B divergent predictions can be illustrated and reported **as descriptive exploratory observations only**, NOT scored as 'appropriate individuality' against independent contextual truth. Do not invent machine-specific labels after seeing model output. R2.3 default `R2_INDIVIDUALITY: UNDETERMINED` unless a **separately frozen, genuinely externally defined contextual truth instrument** is independently reviewed *before* any such scoring. Do not rewrite existing immutable corpus to manufacture a GO.

Probe runs may compare fresh A/B training snapshots on shared and fault probes and inspect change-of-regime behavior, but novelty output must never change protected actions or policies. A 112-byte memory cannot be taken as a humanlike personality.
