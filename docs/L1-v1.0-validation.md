## Analyzer behavior

The explicit command is:

    ./l1_evidence analyze ABSOLUTE_GUEST_PATH \
      --source synthetic-fixture|real-guest-v1

The provenance label is caller-declared, not authenticated and not independent
evidence of how the trace was captured. The analyzer:

1. accepts only a bounded absolute path without a parent component and an
   existing regular file;
2. performs a complete strict V1 validation and checksum pass;
3. derives the 60% development boundary from relative monotonic time;
4. starts evaluation after a 65,000ms embargo with independently initialized
   core and shadow state;
5. replays the complete file and requires unchanged device, inode, size,
   modification time, row count, byte count, and checksum;
6. separately scores `live-default=800/40/150` and
   `v06-trained=2000/75/600`, each static versus the unchanged adaptive shadow;
7. calls `l1_step_at()`, `l1_shadow_step_at()`, and `l1_fixed_prediction()`
   directly rather than reproducing their logic; and
8. emits bounded aggregate output without the private path or raw rows.

All forecasts are sequential and non-overlapping because the unchanged shadow
holds one pending forecast until feedback or rejection. A development forecast
unfinished at the split is never scored, embargo rows are unused, and test
state never carries development adaptation or pending evidence.

Per-class output includes TP/TN/FP/FN, prevalence, recall, specificity,
precision, binary Brier error, false-negative forecast-to-feedback latency,
threshold updates, nonzero and saturated-offset windows, saturation attempts,
and the time/window of the first scored material forecast change, with improved
or worsened correctness. The latency is not event detection delay: it measures
the time from forecast issuance until its future outcome becomes scoreable.
Window output reconciles issued, scored, invalid,
gap/late, reset-discarded and unfinished forecasts, and reports reset events,
delayed feedback, action/core mismatches, and fallback violations. Empty
denominators print `N/A`.

The numerical coverage gate requires at least 30 scored
evaluation windows, at least 80% scored/issued feedback eligibility, and at
least five positive plus five negative outcomes in every class for both
configurations. Exact accounting, core equivalence, and optimized resource
budgets must also pass. Coverage is necessary but cannot establish capture
provenance. Both synthetic input and a caller-declared `real-guest-v1` input
return real evidence as insufficient unless capture authorization and
provenance are independently established outside this CLI.

## Synthetic fixture result

The 7,201-row correctness fixture is deliberately constructed to exercise
both false-alarm and missed-positive adaptation. It is not a sampled workload,
not held-out real evidence, and not evidence of general forecast benefit.

- V1 checksum: `f2aca8af7c6ddd3c`.
- Split: development through 4,320,000ms; evaluation from 4,385,000ms.
- Evaluation observations: 2,816.
- Issued/scored: 47/45; eligibility 0.957447.
- Missing: one invalid discard and one unfinished final window.
- Per class: 23 positive and 22 negative outcomes.
- Feedback elapsed: exactly 60,000ms; no delayed feedback.
- Core/action mismatches and fallback violations: zero.

## Failures and corrections observed during implementation

1. The first expanded fault test expected a reset-caused discarded window, but
   the preceding invalid row had already discarded it. The learner did reset;
   reporting was corrected to distinguish all shadow reset events from the
   narrower reset-discard reason. The algorithm was not changed.
2. That reporting edit initially omitted one `printf` argument. Strict
   `-Werror=format` compilation rejected it before tests; the argument list was
   corrected and all builds passed.
3. The first full suite found CRLF materialization of committed V0.9 golden
   files in the Windows worktree. Content and checksums matched. Golden tests
   now strip only terminal CR for comparison; historical expected output was
   not rewritten.
4. The first sanitizer resource smoke correctly reported 20,260 KiB above the
   optimized 16,384 KiB budget. CI now runs the same instrumented smoke but
   labels its RSS gate excluded; optimized builds alone decide the frozen
   budget. The final instrumented reading was 20,212 KiB.
5. One source-sync attempt used a nonexistent PowerShell installation path and
   stopped before deployment. It was retried with the established script path.

No unresolved code, test, safety, or optimized-budget error remains.

## Post-review scientific corrections

These reporting and test corrections were made after scientific review of
commit `3334f0a5c0f1020cf7c5b7ccec577367c77ddd9a`. They do not change the
frozen split, forecasts, learner, historical synthetic inputs, decision core,
state format, or measurements above.

1. `--source real-guest-v1` now remains explicitly caller-declared and
   unverified. It can pass the separately labeled numerical coverage gate but
   can never independently emit real-evidence readiness. A regression feeds
   the existing synthetic golden trace with that misleading source label and
   requires `REAL_EVIDENCE:INSUFFICIENT reason=unverified-provenance`.
2. The former `miss_delay` fields were renamed to
   `false_negative_feedback_latency`. They measure issuance-to-feedback
   latency for false-negative forecasts, not event detection delay. No frozen
   confusion count, Brier score, or recorded timing value was changed.
3. Each class/configuration now reports saturated-offset forecast windows,
   attempted updates blocked at the compiled offset bound, and the absolute,
   split-relative and scored-window position of the first material forecast
   difference. The new bounded saturation fixture checksum is
   `0bbd76851e142c45`; all pre-existing fixture checksums remain unchanged.

The original optimized measurements remain the historical V1.0 implementation

## Limitations and safety

- There is no authorized real recording, so data readiness and forecast
  transfer remain untested rather than unfavorable or favorable.
- PSI counter rates are observational pressure proxies, not workload truth,
  causal outcomes, energy savings, or proof that an action helps.
- Windows from one trace are time-correlated and are not independent samples;
  no IID significance claim or p-value is produced.
- The caller-declared provenance label and FNV-1a checksum are not
  authentication. Metadata/two-pass checks do not defend against a privileged
  adversary capable of coordinated replacement.
- A single recording may remain underpopulated even when long enough; every
  future session requires separate duration/path authorization and must be
  reported independently.
- No raw trace was committed, uploaded, or printed. No workload was generated.
- No L2/L3, actuator, cgroup/scheduler control, PSI trigger, kernel/device/
  firmware access, host modification, or hardware write was introduced.

The final personal capability assessment remains reserved for the consolidated
stable L1 release candidate under Issue #13.
