## 1. Distinguish three questions

1. **Engineering integrity**: Can a separate, pure, bounded perception adjunct operate safely with no core/OS action coupling and correct cold-start/invalid-data handling?
2. **Contextual detection utility**: Can a memory-conditioned detector distinguish unusual pressure distributions from familiar ones **on independent labeled synthetic episodes**, compared with **strong calibration-tuned static detectors**, for **both** machines at the same false-alarm constraint?
3. **Appropriate individuality**: Do identical pressure probe sequences legitimately warrant **opposite** novelty interpretations because of machine-specific prior operational norms, according to **independent, predeclared machine-conditioned reference truth**, rather than because model state bytes merely differ?

No cross-workflow/owner cognition is being evaluated here. A correct difference means "unusual for this synthetic operational profile," not "fault," "unsafe," or "bad activity." "Normal for this device" MUST NOT override memory protection or other protected advisories.

**Novelty-only constraint:** R2.2's 3×8 per-channel histogram **cannot represent temporal order, causal diagnosis, applications or workflow identity**. Do not test temporal-order-only anomalies as a capability the model should pass; include them as **negative controls** demonstrating a representational limit, reporting that such anomalies are unidentifiable from the current summary. Any eventual temporal-context model needs another frozen design.

## 4. Frozen memory-conditioned novelty rule (separate from R2.3 invalid scorer)

Use the **existing** merged R2.2 `L1OperationalMemorySummary` (three channels × eight coarse histogram bins; no changes to its 112-byte struct, quantizer, admission, decay, or 80-byte checkpoint). Train its A and B references on **V2 training rows only**, with the exact existing `l1_operational_memory_step` and externally asserted quality. Freeze a copy of each supported summary and its checkpoint/hash. Train independent A/B references starting from exactly identical initial empty memory. No labels provided to the histogram.

The novel scorer is proposed as an integer **two-sided empirical-tail surprise**; its goal is to recognize pressure values rare on *either* side of machine's learned reference, including unusual decreases. Per eligible observation and channel `c`, determine R2.2 quantized bin `b` using the already-frozen 3000/100/500 bp bin thresholds. For histogram counts `h[0..7]` and sum `n>0`:
```
left  = sum(h[0] ... h[b])
right = sum(h[b] ... h[7])
tail  = min(left, right)
score_c = max(0, 1024 - floor((2048 * tail) / n))
row_score = max(score_cpu, score_mem, score_io)
```
Use >=32-bit intermediate multiplication, bounded integer arithmetic, no float or learner-parameter updates. A zero-count previously unseen bin can score 1024. `score_c` is a **relative tail-surprise index**, not a calibrated probability of a fault. Require supported, internally consistent reference counters and `quality=OK`, valid `0..10000bp` fields and valid caller freshness status, else `UNKNOWN`. Candidate fixed *global* row-score thresholds `{128,256,384,512,640,768,896,960,1000,1024}`; 1024 permits an all-negative fallback only if truly no row hits under observed references. At episode level `SUSPECTED` iff **>=5 eligible rows** exceed threshold, `EXPECTED` otherwise, but if <10 eligible => `UNKNOWN`. Freeze unchanged across A/B. Do not feed scores into RC0 actions.

**Known limits:** 8-bin quantization can merge distinct physical PSI values; marginal-only histograms miss temporal correlations and may be unable to separate subtle modes. Non-identifiability, all-UNKNOWN, or worse-than-fixed results should be reported candidly as NO_GO/UNDETERMINED, never explained away by moving thresholds after held-out.

## 5. Competing baselines — no strawman

Evaluate all detectors on *the same eligible episodes and observation cadence*, with the same known/unknown reporting:
1. Always UNKNOWN integrity/abstention control.
2. Immutable **V1 original fixed** CPU>=6000, mem>=400, IO>=2000 with >=5 hits, as a historical reference (not only hurdle; never modify frozen JSON).
3. Calibration-tuned **per-machine high-side threshold** comparator, using R2.3's fair full grid CPU {1000,2000,3000,4500,6000,8000}, mem {25,50,100,200,400,800}, IO {250,500,1000,2000,3000,5000}; hit K {1,3,5,8,12}, exactly 1080 variants/machine.
4. A **strong per-machine two-sided static band** reference, trained once from **training-split valid normal rows** using only training labels (a *deliberately strong supervised comparator*) and calibrated on calibration episodes. Derive for each channel the sorted eight-bin distribution of normal training observations. Form six fixed candidate bands per channel by excluding the lowest/highest `q`-fraction of training-normal counts, with `q in {0,1,2,5,10,20}%`; boundaries are deterministic bin lower/upper edges and ties choose the broadest band. For each machine use the **same** q on all three channels for a given candidate; a row hits if any channel lies outside its candidate band. Episode K from {1,3,5,8,12}. Thus **30 candidates per machine**, plus baseline 3, fixed before calibration. This comparator has profile information via static learned limits; the novelty system may not claim a win over a weak fixed threshold while losing to this stronger static alternative.
5. Freeze **the strongest eligible fixed model** per machine from (2–4) using calibration **only** under the selection rule below; report all three reference families on held-out, regardless of strongest selection. The scorer can use its training-only histogram, while a supervised comparator uses training labels; document the asymmetric information transparently.

**Calibration selection**:
- Each fixed candidate is feasible only if its calibration normal-episode FPR <=10% and has >=10 scoreable normal and >=10 positive episodes/machine. Pick feasible candidate with **highest sensitivity**, then lowest FPR, then choose high-side over two-sided on exact ties, then lexicographically smallest parameter tuple. If no feasible candidate, choose the minimum FPR/maximum sensitivity candidate for descriptive reporting but mark `CALIBRATION_CAP_NOT_MET`, forbid scientific GO.
- Novelty has **one globally fixed threshold** chosen from the list above. Feasible only if **both machines individually** <=10% calibration FPR and >=10 normal/positive scoreable episodes. Pick maximum of the **minimum A/B sensitivity**, then maximum A+B sensitivity, minimum maximum FPR, minimum sum FPR, then **highest threshold**. If no feasible threshold, select 1024, record failed cap and forbid GO.
- Freeze all selected values and source/data identities in the calibration lock, **before first held-out access**. Do not calibrate using shared probes, regime-shift, or old R2.3 exposed held-out.

## 6. Scoring, gates, probe truth and nonregression

Primary unit = frozen independent `episode_id`. Recompute eligibility independently; explicitly exclude only invalid/unavailable sensor quality, invalid values, inconsistent timestamp and stated predeclared reason; report excluded by reason. Predicted UNKNOWN is an abstention, **not** a true negative. Every model reports TP, FN, TN, FP, unknown positives/normal, scoreable denominators, coverage, per-family counts, and false reassurance. If coverage differs across candidates, evaluate common eligible episodes and report unequal coverage; material disparity => `R2_UTILITY: UNDETERMINED`.

**Sufficient support:** each A and B heldout >=20 independent normal and >=20 positive scoreable episodes; at least one family/machine with >=5 independent positive episodes. Otherwise INSUFFICIENT_SUPPORT. Never report bin/row counts as independent event replicates.

**Utility GO requires ALL**: corpus/metadata valid; calibration lock predates heldout; novelty caps met; both machines' novelty heldout FPR <= **strongest fixed** heldout FPR and sensitivity >= strongest fixed; **strictly more true positives** on at least one predeclared family with >=5 independent positive episodes; zero hidden abstentions/exclusions; immutable protected action and state equivalence; resource gates pass. Failing valid comparison => NO_GO. Invalid study metadata/data leakage => INVALID and utility UNDETERMINED; insufficient independent episodes => INSUFFICIENT_SUPPORT.
