# HMI L1 R2.3c — Evaluation preflight architecture and Codex handoff

**Status: docs-only architecture before any preflight implementation; no new heldout experiment is authorized.**

Companion authoritative first commit: `docs/L1-r2.3c-evaluation-plan.md` at `548307598a304bb00fccef5b8510a2b2321d0131`. Tracking [issue #31](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/31). Baseline is merged **R2.2 `main`** `0a06a0828e08b7fd6144211c73e7ce48d4cc8e73`, not open invalid PR #28 or #30.

## 1. Intent: build a trustworthy scientific instrument, not another model

Two experimental attempts have stopped without producing valid R2 novelty evidence:
- V1 R2.3 had an eligibility-table discrepancy (nominal counts vs actual post-fault eligible rows) and descriptively worse novelty than a tuned fixed comparator.
- V2 R2.3b fixed episode counts but did not exercise real R2.2 **post-reset** reference-support logic before freezing the corpus. Machine A's final timestamp-regression reset came too late for four observed five-minute buckets after it. A scorer trained on an unsupported summary cannot fairly calibrate.

The invalid R2.3b evaluator additionally had latent, **not-run-to-completion** bugs: novelty's episode K accidentally followed `HighConfig.k` (zero on calibration); probe mode printed completion without comparing to machine-conditioned truth; and lock mode accepted nonempty SHA fields without recomputing their real content. These are reasons to validate the *harness* before spending time on a third full corpus.

**R2.3c must avoid outputting any novel anomaly scores on scientific heldout data.** Its purpose is to prove stop/fail conditions and honest negative controls with tiny, artificial known-answer cases.

## 2. Component model — strictly offline

```text
                 immutable original V1/V2 identities
                 (only selected training input is read)
                                    |
                 new offline preflight known-answer fixtures
                                    |
                     +--------------+--------------+
                     |              |              |
                   Gate A         Gate B          Gate C
                 real R2.2       novelty K=5     hash + calibration
                 memory replay   episode rules   lock verifier
                     |              |              |
                     +--------------+--------------+
                                    |
                            Gate D / Gate E
                    probe truth / metadata / isolation
                                    |
                        R2_3C_PREFLIGHT result
                           PASS|FAIL|NOT_RUN
```

All preflight modules live outside production monitor/PSI adapter and never feed into `l1_step_at`, core policy, shadow or persistent V1/V2 state. No new L1 live observation / daemon or network protocol.

## 3. Test-first files — recommended implementation artifacts

Under `src/level1/evaluation/`:
- `l1_r23c_support_preflight.c` — strict bounded CSV train-only loader and actual R2.2 `l1_operational_memory_step` replay; precise last-reset/time-bucket/support audit and small in-process good/bad fixtures.
- `l1_r23c_decision_preflight.c` — pure episode-aggregation known-answer tests with model-specific K and deliberate K=0 mutation negative case.
- `verify_r23c_lock.py` — stdlib-only SHA256 file verification, exact canonical lock grammar, duplicate rejection, rerun calibration on tiny fixed fixtures and match output hashes; deliberately modified file/input/tuple rejection. *SHA is not authentication*.
- `verify_r23c_probes.py` — strict separate truth-file loading and ID/byte-equality/coverage checks; compare pre-scripted known-answer outputs (explicitly fixtures, not model-predicted performance).
- `verify_r23c_eligibility.py` — independently recompute actual post-fault eligible rows and validate negative regression fixture, without modifying V1/V2 historical files.
- `r23c_preflight.sh` or a Makefile `r23c-preflight` target — executes gates A–E with individually reported statuses, failing command on any required failure and printing a composite summary only if every gate ran. Make tests `-DNDEBUG` resistant, normal strict `-std=c11 -Wall -Wextra -Werror -Wpedantic`; use existing ASan/UBSan/leak and source audit. No extra heavy dependencies.
- `docs/L1-r2.3c-validation.md` — final outcome report only after implementation, including exact source/test SHA identities, clean CI logs, expected historical negative, proof heldout was never opened, guest compiler details and any outstanding limitations.

Names are suggestions; invariant tests and frozen protocol semantics are the binding requirements. A smaller implementation with fewer files is preferable if it keeps failures independently observable.

**Avoid copying PR #30 evaluator into R2.3c as a working candidate without a line-by-line audit.** A dedicated test helper that *proves the erroneous K coupling fails* is safer. Preserve PR #30 source and results for historical reproducibility.

## 4. Preflight must fail for the right reason

### A — Supported reference
Run real `L1OperationalMemory` with actual sample quality/timestamps. Reproduce the frozen V2 machine-A training result as expected unsupported; run known-answer positive case after four real observed buckets and 256 accepted samples; test explicit and implicit resets, invalid/no-reset distinction, and restored freshness. A single last-minute `quality=REGRESSED` must not leave a falsely supported model.

### B — Five-hit novel episode rule
Test deliberately adversarial configurations: a comparator with `k=0` must be rejected, while novelty remains K=5 even when comparator K is 1,3,8,12. At 4 novelty hits classifier says EXPECTED; at 5 it says SUSPECTED when >=10 valid rows; with 9 valid rows it says UNKNOWN.

### C — Data-binding lock
Verify every listed source/CSV/config/recalibration result against actual bytes and fixed selection logic. Removing, editing or swapping even one legitimate-source field must cause a pre-heldout failure. A lock that merely contains nonempty checksum-looking text is invalid. Tiny mock calibration fixture selection is allowed only as a harness test; **do not select actual future V3 threshold in R2.3c**.

### D — Machine-specific contextual truth
Test two identical probe observation sequences supplied to both A/B, with independently prepared A/B expected labels. The test must actually load the truth table and compare each prediction and every relevant ID. Inject a wrong B interpretation to demonstrate failure; do not label a canned test a scientific success.

### E — Eligibility and action noninterference
Independently reconstruct eligibility and fault metadata. A nominal 40-row episode containing an `ABSENT` row must have 39 eligible; the bogus declared 40 fails. Compare protected 104B core, shadow and published actions byte-for-byte on/off across replay; all legacy tests still pass unchanged.

## 5. Required execution order

**Stage 0 — already complete:** issue, branch and first research protocol; this architecture second.

**Stage 1 — Codex implementation:** add only lightweight, test-only preflight programs/helpers and tiny deterministic in-memory or tiny generated unit fixtures. Do **not** add V3 heldout, copy old V1/V2 into new study, or implement new novel L1 runtime algorithms.

**Stage 2 — qualification:** local strict normal/NDEBUG/ASan/UBSan/leak; `make rc0-ci`, `make rc0-qualification` in isolated Debian QEMU; exact source audit, no protected-core regression. If transient benchmark p95 fails, preserve first miss and reruns, never relax existing threshold. Existing CPU/RSS budgets remain binding; no real sensor or overhead-benefit claim.

**Stage 3 — report and review:** update draft PR with `R2_3C_PREFLIGHT: PASS|FAIL|NOT_RUN`; show individual gate results and negative controls plus historical invalidity. Leave unmerged for independent review, no automatic action on V3.

**Stage 4 — future only if separately approved:** design a genuinely fresh V3 synthetic study *after* a green preflight, and require training support simulation on both streams **before the new corpus freeze**. That later study must freeze its own detector, baseline, calibration and truth procedures prior to coding/heldout; it is not part of R2.3c.

## 6. Safety and scientific status

Do not alter any of: L1Core, L1Shadow, R2.1 classifier, R2.2 operational memory, persisted V2 state, previous frozen data, legacy policies, historical GO/NO_GO and invalid result reports. No real PSI sampling, load generation, privileged OS changes, network listener, app-level/user profiling, production L2/L3, host modifications, or actual resource actuation. Any scientific observation stream requiring host/guest data is a separate future request.

**L1 is a bounded machine sensory/reflex element; broader proactive personal intelligence belongs to future L2/L3.** A passing R2.3c preflight does not change that architectural boundary.
