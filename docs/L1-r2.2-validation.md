## Implementation

`l1_operational_memory.h/.c` adds an independent 112-byte in-memory object:

- three channel-major eight-bin `uint16_t` histograms using the frozen
  3000/100/500 bp descriptors;
- strict quality, range and monotonic-time admission with a 1,000 ms minimum;
- explicit regression/reset clearing only the new memory;
- observed five-minute support buckets without inferred gap samples;
- 256-sample/four-bucket support and 128-sample/two-bucket restore freshness;
- per-channel deterministic halving before an update when its sum is at least
  1,024, plus saturating counters;
- no heap, filesystem, clock, network, policy, protected action or actuator
  interface.

The separate checkpoint is exactly 80 initialized little-endian bytes with
magic/version/length, 48 histogram bytes, bounded support fields, aggregate
decay count and reflected IEEE CRC32. Decode rejects bad structure, CRC,
reserved bytes, length and impossible support/bin combinations. Any failure
returns the new object to an empty `WARMING_UP` state. The CRC detects accidental
corruption only; it provides no authentication, replay defense or authority.
The existing protected 72-byte V2 state is unchanged.

## Limitations

- Inputs and quality labels are caller-supplied aggregate synthetic evidence;
  the module cannot prove provenance, staleness or causation itself.
- PSI stall values are not utilization, physical device health, application
  identity, user behavior or intent.
- `SUPPORTED` is only a sample/bucket sufficiency heuristic, not calibrated
  confidence or independence.
- Fixed five-minute wall-clock buckets can straddle regime boundaries and do
  not establish independent events.
- Decay is a deterministic bounded histogram heuristic, not learned policy,
  forecasting or outcome-aware optimization.
- CRC32 protects accidental integrity only. The checkpoint has no trust anchor,
  authentication, authorization or anti-replay guarantee.
- Synthetic A/B divergence was engineered and no R2.2 held-out usefulness
  score was calculated. R2.3 remains responsible for any independent novelty
  and tuned-fixed comparison.
- Microbenchmark and unit success cannot establish generalized intelligence,
  real workload transfer, anomaly detection benefit or resource savings.
