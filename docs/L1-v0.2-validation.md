# HMI Level 1 v0.2 implementation and validation report

Date: 2026-10-22
Scope: native C11 Level 1 only; read-only observation and recommendation.

## Audit findings from v0.1

The existing implementation already had a small deterministic core, fixed-point
inputs, compiled safety ranges, strict policy parsing, fail-safe `HOLD`, bounded
debounce adaptation, and no actuator. The following limited scientific claims:

1. Decision tests covered isolated examples but not complete, explicit pressure
   traces with a known expected action at every sample.
2. Policy tests did not cover malformed, missing, duplicate, or unknown fields,
   did not prove rejected updates preserve all state, and defined no rollback.
3. The only benchmark timed `l1_step()` in-process. It had no fixed comparator
   and omitted PSI acquisition/parsing, process CPU time, and process RSS.
4. Benchmark output had no repeated-run harness or captured guest environment.
5. The policy file is unauthenticated and state is process-local. PSI is global
   to the guest, not workload-scoped. Adaptation is heuristic, not learning or
   evidence of improved resource management.
6. `assert`-based tests would disappear if compiled with `NDEBUG`; the supplied
   Makefile does not define it, but a future harness should use explicit checks.
7. The monitor reports recommendations but does not persist decisions or policy
   history, and restart loses the rollback snapshot and adaptation state.

## v0.2 changes

- Added deterministic CPU, memory, I/O, priority, hysteresis, and invalid-input
  traces with an exact expected recommendation for every sample.
- Expanded negative policy tests and checked byte-for-byte state preservation
  after rejected updates.
- Added one-snapshot rollback. A rollback requires a new generation greater
  than the active one, restores only previously validated parameters, and
  resets runtime state to `HOLD`.
- Verified adaptation increases by at most one step per 600 valid observations
  and returns one step after a stable window; the compiled range remains 0..2.
- Added a fixed-rule comparator and separate `core` and `live` benchmark modes.
  Live mode includes three Linux PSI reads, parsing, and the decision; it reports
  wall time, process CPU time, CPU ns/sample, valid observation count, and peak
  process RSS; it fails if any live observation is invalid.
- Kept the executable single-threaded and allocation-free in the decision path.
  No resource-control code, L2/L3, scheduler, kernel, firmware, or hardware write
  was introduced.

## Reproduction in the Debian QEMU guest

From the Windows source-of-truth workspace:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync-source.ps1
ssh -p 2222 lab@127.0.0.1 "cd /home/lab/hmi/src/level1 && make clean all test"
ssh -p 2222 lab@127.0.0.1 "cd /home/lab/hmi/src/level1 && sh ./run_benchmarks.sh 5 10000 10000000"
ssh -p 2222 lab@127.0.0.1 "cd /home/lab/hmi/src/level1 && ./l1_monitor --samples 8 --interval-ms 250 --policy policy.example"
```

No command requires `sudo`. The benchmark CSV repeats its header for each
independent process invocation so each result remains self-describing.

## Recorded guest results

Validated on Debian GNU/Linux 13.7 (trixie), kernel
`6.12.113+deb13-amd64`, x86-64, with Debian GCC/cc 14.2.0-19. The build used
`-std=c11 -O2 -Wall -Wextra -Werror -Wpedantic` and emitted no warnings.

`make clean all test` passed:

- policy safety fallback, complete compiled bounds, schema/generation checks,
  rejected-update state preservation, monotonic rollback, slow adaptation, and
  PSI parsing;
- CPU threshold/hysteresis trace: 8/8 expected decisions;
- memory/I/O/CPU priority trace: 9/9 expected decisions;
- invalid telemetry reset trace: 6/6 expected decisions.

Both test binaries also passed under GCC AddressSanitizer and
UndefinedBehaviorSanitizer with leak detection enabled. A normal optimized
build was restored and passed again afterward.

The eight-sample monitor smoke run loaded validated policy generation 1 and
reported eight valid observations with `HOLD`, `self_extra=0`, CPU PSI between
0.27% and 0.33%, and memory/I/O full PSI at 0.00%. It ran as unprivileged user
`lab` and printed the v0.2 read-only advisory warning.

Five benchmark repetitions used 10,000,000 core samples and 10,000 live PSI
samples per engine. All 100,000 requested live observations (50,000 fixed and
50,000 L1) were valid.

Core medians were 2.203 ns/decision for the fixed rule and 11.760 ns/decision
for L1, an observed incremental median of 9.557 ns. Live process-CPU medians

Median wall time for 10,000 live samples was 0.886669 seconds fixed and
0.933483 seconds L1. These processes ran sequentially, not simultaneously.

## Read-only and repository audit

The production sources contain no process-priority, scheduler, cgroup, device,
`ioctl`, subprocess, kernel, firmware, or hardware-control API. Their only file
opens are `fopen(..., "r")` for policy memory and `/proc/pressure`; output is
limited to stdout/stderr. The unit test alone creates a unique temporary file
under `/tmp` to exercise hostile policy text, then unlinks it.

The tracked-file and secret-pattern audit found no virtual disks, VM backups,
compiled binaries, private keys, common token forms, or environment-secret
files. `.gitignore` excludes the entire `vm/` tree, common virtual-disk formats,
all four Level 1 binaries, object/executable files, `.ssh/`, `.env*`, PEM files,
and key files. The local `vm/` directory was confirmed ignored.

## Interpretation limits

The fixed rule intentionally uses the same thresholds and priority order but no
confirmation, hysteresis, or adaptation. It is an overhead comparator, not a
claim that either controller improves workload outcomes. Live runs read changing
guest-wide PSI values; repetitions estimate overhead variability but do not make
the observed pressure trace identical. `ru_maxrss` is a peak, process-wide Linux
measurement and commonly resolves only to a page. Core nanoseconds can be below
timer or frequency-noise significance, so report the repeated range or median.

The live run observed pressure below every decision threshold, so both live
checksums were zero (`HOLD` throughout). It validates the real read/parse/decide
cost but not transition cost; deterministic synthetic traces cover transitions.
Fixed and L1 processes ran in a fixed sequential order, so cache warmth and
changing VM/host load can bias the comparison. Five repetitions are descriptive,
not a confidence interval, and no CPU affinity, frequency control, warm-up,
randomized ordering, or independent workload was used. The roughly 84-106 us
PSI observation cost dominates the approximately 12 ns L1 core median, so this
experiment cannot attribute the overlapping live difference to L1 itself.

The policy file and rollback snapshot remain unauthenticated and process-local.
An in-process memory-corruption bug or hostile code in the same address space is
outside this prototype's protection model. Restart discards rollback and learned
debounce state. The public C structure is not a security boundary; a future L2
must communicate through a separately authenticated and authorized interface.

Level 1 v0.2 remains a research prototype. Resource-control experiments require
a later, separately authorized design with scoped cgroup ownership, outcomes,
kill switch, durability, and failure recovery.
