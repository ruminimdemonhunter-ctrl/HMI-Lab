# HMI Level 1 v0.5 frozen risk-aware-memory protocol

Status: **frozen before implementation, candidate execution, or held-out
execution**. Issue: [#5](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/5).
Base commit: 0e43eb8819f5fbf8d7cd2daeb489030c32d10679.

Changing the algorithm below, generator, seeds, search, loss, tie-breaks,
metrics, or guardrails after this commit invalidates the held-out result and
requires a separately named evaluation version. Compile and reporting fixes
that do not affect decisions or scoring must be disclosed.

## Hypothesis and four controlled candidates

Action-specific bounded adaptation can suppress noisy CPU and I/O responses
without adding any memory-protection confirmation delay relative to a strong
training-tuned fixed controller. Every candidate calls the same real
l1_step_at() once for each identical observation and timestamp.

1. **Frozen default**: compiled default policy, adaptation disabled.
2. **Tuned fixed**: best policy selected only on fresh training scenarios,
   adaptation disabled.
3. **V0.4 legacy global**: tuned policy with the exact V0.4 global
   debounce_extra algorithm and bounds.
4. **V0.5 risk-aware**: tuned policy with the frozen action-specific algorithm
   below.

The evaluator may select only a compiled adaptation mode. This control is not
policy writable, persisted, or remotely accessible. Production initialization
selects risk-aware mode. The V0.4 evaluator and replay explicitly select legacy
mode so their historical comparator remains reproducible.

## Frozen risk-aware algorithm

The policy confirmation_samples remains the base confirmation count.
cpu_debounce_extra and io_debounce_extra are independent unsigned values in
0..2. There is no memory debounce extra.

- A requested PROTECT_MEMORY transition uses an independent
  memory_candidate_streak and exactly confirmation_samples. CPU/I/O candidate
  changes cannot reset this streak. No adapted value can increase memory entry
  confirmation.
- Other transitions use the existing candidate/streak mechanism. A transition
  whose requested action is PREFER_INTERACTIVE uses cpu_debounce_extra; one
  whose requested action is DEFER_IO uses io_debounce_extra. A transition from
  CPU or I/O to HOLD uses the extra for the action being left. CPU-to-I/O uses
  the I/O extra; I/O-to-CPU uses the CPU extra. Leaving memory for HOLD uses no
  extra; leaving memory for CPU/I/O uses the requested action's extra.
- Confirmed transitions involving CPU increment the saturated CPU switch
  counter; transitions involving I/O increment the saturated I/O switch
  counter. Transitions to or from memory do not increment either counter, so a
  safety escalation is not learned as CPU/I/O noise.
- A shared window advances only on valid, non-regressing observations while
  risk-aware adaptation is enabled. Both 600 valid samples and 600,000 elapsed
  monotonic milliseconds are required. At a gate, each action updates
  independently: at least 8 switches increments its extra by one, zero switches
  decrements it by one, and 1..7 leaves it unchanged. Values saturate at 0..2.
  Counters reset after the gate. One window can update both actions once.
- Invalid observations and regressing time return HOLD, reset candidates and
  the independent memory streak, and do not advance the adaptation window.
  Policy apply, rollback, mode change, initialization, and recovery reset all
  runtime counters/streaks and fail closed at HOLD.

The legacy mode retains V0.4's one global extra, one switch count, and identical
600/600000 gates. Runtime L1 observes only telemetry, monotonic timestamps, and
its bounded internal history; oracle labels never enter adaptation.

## Persistence decision

Saving writes a strict 72-byte state format version 2 with a new magic, CRC32,
active policy, one rollback snapshot, has-previous flag, and only the two
risk-aware extras. Runtime actions, candidates, streaks, switch/sample counters,
timestamps, mode, and the legacy global extra do not persist.

Loading accepts:

- valid v2: restore validated policies and bounded CPU/I/O extras, with
  risk-aware mode and all runtime state reset;
- valid 64-byte v1: validate the complete old encoding, migrate only active and
  previous policies, deliberately discard its global debounce_extra, initialize
  both new extras to zero, select risk-aware mode, and reset runtime state;
- anything else: compiled defaults and HOLD.

V1 bytes are never reinterpreted as action-specific values. Saves after a v1
load produce v2. Both formats retain mode-0600 atomic replacement, file and
parent-directory fsync, one-snapshot rollback, and CRC integrity (not
authentication).

## Deterministic generator and independent truth

The evaluator uses the V0.4 PCG-XSH-RR32 and SplitMix64 implementations, integer
sampling, clamping, and explicit little-endian FNV-1a trace checksum. Each
scenario derives separate truth and observation-noise streams from its base
seed and family ID. No live PSI, platform randomness, wall time, or held-out
feedback is used.

Oracle priority remains memory > I/O > CPU > HOLD. Each contiguous
oracle-visible non-HOLD segment is one event. Truth is created before noise and
never inferred from observations.

Regular cadence is 1,000 ms. Baseline observations are CPU 600, memory 10, I/O
50 basis points. Sustained CPU/I/O event observations are 3,600/750; ordinary
memory events are 180; severe memory is 400; near-threshold memory is 115.
Base independent uniform noise is CPU [-400,+400], memory [-35,+35], and I/O
[-150,+150], clamped to 0..10000. Start jitter uses the truth stream and is
inclusive; noise and false-response features use only the noise stream.

## Fixed-policy training and manifest

Training searches the same bounded 108-point Cartesian space:

- CPU trigger 2000/3000/4000;
- memory trigger 50/100/200;
- I/O trigger 300/500/800;
- confirmation samples 2/3/4/5;
- schema 1, generation 1.

The primary loss remains exact quarter-points:

loss = FP*1 + missed_CPU*4 + missed_IO*6 + missed_memory*10 + switches*0.25

Wrong actions during an event count as a miss for the oracle class, not an
additional false positive. Tie-breaks remain memory misses, memory undetected,
I/O misses, I/O undetected, CPU misses, CPU undetected, false positives,
switches, then lexicographic (confirmation, CPU, memory, I/O).

Training writes a strict manifest containing protocol ID, training checksum,
candidate count, selected policy fields, loss quarter-points, and deterministic
policy fingerprint. Before held-out execution, those exact training outputs are
pinned in source/tests. Held-out accepts only that manifest and verifies all
fields before generating held-out traces. The fingerprint is an experiment
identity check, not authentication.

Trace generation is excluded from CPU timing. Held-out traces are generated

remain separate measurements.

## Guardrails and scientific decision

The evaluator fails on any invalid/regressing-time non-HOLD response, adapted
value outside 0..2, policy/manifest mismatch, or trace checksum mismatch.

Risk-aware passes the memory guardrail only if, versus tuned fixed:

1. aggregate and every-family memory misses do not increase;
2. no paired memory event is detected later;
3. memory undetected events and aggregate maximum delay do not increase.

I/O misses, undetected events, and delays are an independent secondary
guardrail and every regression is reported. All other unfavorable tradeoffs
remain visible.

A **RESEARCH_GO** requires the memory guardrail, no fallback/bound violations,
risk-aware loss no greater than tuned fixed, fewer switches than tuned fixed,
and risk-aware loss lower than legacy global. Otherwise the result is
**NO_GO**. RESEARCH_GO would authorize only further read-only research, never
resource actuation.

## Required validation and safety

Before reporting: normal tests, NDEBUG, ASan/UBSan/leak tests, sanitizer-backed
evaluation smoke, deterministic replay, five-run benchmark, one optimized CI
evaluation, and the single 100-repetition held-out run execute in the Debian
QEMU guest. GitHub Actions runs build/test and sanitizer evaluation.

The work remains unprivileged and recommendation-only. It adds no L2/L3,
neural network, scheduler/cgroup control, kernel/device/firmware interface,
network update service, or hardware write. Results are synthetic evidence about
these frozen traces only.
