# HMI Level 1 v0.5 risk-aware memory design

V0.5 remains a deterministic, allocation-free C11 recommendation core. It
changes only bounded internal behavior memory and adds no actuator or authority.
The immutable priority remains memory > I/O > CPU > HOLD.

## Runtime modes

The compiled core exposes three research modes:

- disabled: fixed policy behavior;
- legacy global: the exact V0.4 global debounce comparator;
- risk-aware: independent CPU and I/O extras with non-adaptive memory entry.

Production initialization selects risk-aware mode. The mode is not accepted
from policy files, not persisted, and not remotely writable. The compatibility
l1_set_adaptation_enabled helper selects legacy-global when enabled so the
frozen V0.4 evaluator remains reproducible.

Risk-aware memory entry has an independent streak and always requires exactly
the policy confirmation count. CPU and I/O extras range only from zero to two,
change by at most one after both 600 valid observations and 600,000 monotonic
milliseconds, and reset on initialization, policy apply, rollback, mode change,
or recovery. Invalid data and time regression fail closed to HOLD.

## Persistent state compatibility

V0.5 writes a new 72-byte version-2 encoding:

| Offset | Size | Field |
|---:|---:|---|
| 0 | 8 | HMIL1S2 magic |
| 8 | 4 | format version 2 |
| 12 | 4 | encoded size 72 |
| 16 | 15 | active validated policy |
| 31 | 1 | CPU debounce extra, 0..2 |
| 32 | 1 | I/O debounce extra, 0..2 |
| 33 | 1 | previous-policy-present flag |
| 34 | 6 | zero reserved |
| 40 | 15 | previous validated policy or zeros |
| 55 | 13 | zero reserved |
| 68 | 4 | CRC32 over bytes 0..67 |

The loader also recognizes and fully validates the old 64-byte version-1
encoding. It migrates only policy memory and the one rollback snapshot. The old
global debounce value is intentionally discarded, and both action-specific
extras start at zero. The next save writes v2. Unsupported, corrupt, oversized,
malformed, or out-of-envelope files recover compiled defaults and HOLD.

Atomic same-directory replacement, mode-0600 temporary files, file fsync,
directory fsync, and CRC behavior are unchanged. CRC detects accidental
corruption; it does not authenticate state.

## Scope

The core still reads no clock, filesystem, operating-system control, device, or
network interface. The caller supplies observations and monotonic timestamps.
Persistence is explicit local behavior memory only. There is no L2/L3,
scheduler, cgroup, kernel, firmware, or hardware-control implementation.
