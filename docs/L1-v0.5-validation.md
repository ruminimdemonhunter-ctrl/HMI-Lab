# HMI Level 1 v0.5 validation report

## Scientific outcome

**NO-GO.** Risk-aware adaptation removed V0.4's extra memory-confirmation
delay, but it did not beat the newly tuned fixed controller under every frozen
criterion. The memory guardrail passed: all 70 paired memory events had equal
detection delay, aggregate memory misses remained 249, no memory event was
undetected, and there were no invalid-data or regressing-time fallback
violations. However, risk-aware I/O adaptation increased I/O missed samples
from 76 to 86 and I/O p95 delay from 1 to 3 samples relative to tuned fixed.

Risk-aware total loss was 9,580.25, worse than tuned fixed at 9,111.00 but
better than V0.4 legacy global adaptation at 9,936.75. It reduced action
switches from tuned fixed's 1,052 to 1,017. Those partial improvements do not
override the preregistered all-criteria gate.

This is evidence about deterministic simulations only. It does not establish
real workload optimization, learned improvement, or generalized intelligence,
and it does not authorize resource actuation.

All 100,000 live observations were valid. The live measurement is dominated by
three Linux PSI reads and parsing, is sensitive to guest load, and is not a
workload-benefit measurement. `ru_maxrss` is process-wide and coarse. The
held-out evaluator's 6,572 KiB RSS includes all generated traces, stored
metrics, four controller result sets, and libc—not the allocation-free core
alone.

Five deterministic V0.3 replay repetitions also passed. Fixed CPU cost ranged
23.807..28.220 ns/decision; bounded legacy adaptation ranged
26.561..33.430 ns/decision. That historical replay is retained for regression
coverage and is not the V0.5 scientific comparison.

## Persistence and safety validation

V0.5 writes the explicit 72-byte `HMIL1S2` format with CRC32, zero-reserved
fields, action-specific extras, mode-0600 temporary creation, file `fsync`,
atomic same-directory replacement, and directory `fsync`. The loader accepts a
fully validated 64-byte V0.3/V0.4 v1 state, migrates only policy and rollback
memory, discards the old global extra, initializes both action-specific extras
to zero, and writes v2 on the next save. Corrupt, oversized, malformed,
out-of-envelope, and incompatible state safely recover compiled defaults and
`HOLD`. CRC is corruption detection, not authentication.

Normal, `NDEBUG`, ASan, UBSan, leak, deterministic trace, policy rejection,
saturation, invalid-observation, time-regression, priority, persistence,
migration, rollback, benchmark-argument, evaluator-argument, and frozen
manifest-identity checks passed in the Debian QEMU guest. The sanitizer-backed
held-out smoke test reproduced checksum `64568259bcad8d75` and NO-GO.

A source audit found no scheduler, cgroup, kernel-control, device, firmware,
network-update, or hardware-write interface in L1. Linux integration remains
read-only PSI observation; decisions are recommendations only. Git inspection
found no credentials, virtual disks, backups, or compiled binaries in the
change set.

## Limitations

- Latent truth, noise, and workload regimes are synthetic.
- Samples are scored equally within the declared weighted loss; the experiment
  does not measure throughput, latency, energy, or user-visible utility.
- The newly tuned fixed policy may overfit the small training split despite the
  strict held-out separation.
- CPU timing at tens of nanoseconds is compiler-, VM-, and host-load-sensitive.
- The evaluator reports one process RSS high-water mark for every controller.
- State integrity is not authenticity; a future authorized updater still needs
  provenance, access control, and audit design.
- No actuator was tested or implemented. A future milestone requires separate
  review and new real-workload evidence.
