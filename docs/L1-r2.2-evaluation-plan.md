## 1. Research mission and scientific limits

Build a tiny **machine-condition operational memory** that accumulates bounded statistical summaries of validated, nonpersonal Linux PSI-style observations. The intended future purpose is to tell L2 how this particular machine's pressure rhythms evolve. It cannot infer applications, intentions, wellness, device faults, user identity, personality or resource optimization, and it must not learn new protection policies.

**R2.2 primary engineering result:** a separate <=512-byte C11 state whose summaries evolve deterministically with different synthetic histories, survive bounded save/restore and reset safely, and have strictly zero effect on legacy L1 actions. **R2.2 must NOT score novelty/anomaly superiority or declare useful machine individuality.** Those need the independent R2.3 preregistered hold-out and tuned-fixed comparison. A/B memories being different is not a scientific success by itself.

Historic V0.4/V0.5 adaptation NO_GO, V0.6 shadow/action coupling NO_GO, V0.7 diagnostic NO_GO, insufficient real evidence, undetermined real forecast transfer, blocked production L2 auth and blocked V1.2 benefit experiment are immutable.

## 2. Code, data and authority boundaries

- New pure C11 `l1_operational_memory.h/.c` beside existing `l1_perception.h/.c`. Do not edit protected `l1_core.c`, `l1_shadow.c`, `l1_policy.c`, `l1_state.c`, `l1.h`, `l1_shadow.h`, old golden/held-out fixtures, policy or action enum. L1Core 104B, L1Shadow 208B, existing V2 state 72B unchanged.
- Source inputs: a by-value `L1Observation`, externally validated `L1PerceptionInputQuality`, and `uint64_t monotonic_ms`. Use R2.1's existing externally supplied quality contract. No access to active policy, L1Core, protected advisory action, L2/3, filesystem, clock, global mutable state, network, process identity or personal context.
- Returned observations are aggregate-only: `WARMING_UP | SUPPORTED | INVALID | RESET | RESTORED_UNVERIFIED`, sample/window support, per-channel quantized histograms. An observed `SUPPORTED` means **enough eligible history to describe**, NOT calibrated anomaly confidence or a real device-health grade.
- `l1_step_at()` remains the sole published advisory action authority. No memory/quality/novelty feedback into core or shadow. Core byte and action equivalence against observer-off baseline on **every** tested row.
- No production runtime or daemon integration; no new automatic telemetry sampling. Offline test harness may write only finite, private temporary fixtures. No host Windows changes.

## 3. Frozen bounded representation and update algorithm

**Quantization:** 3 independent pressure channels (CPU some, memory full, I/O full), each with **8 integer bins**, represented by `uint16_t bins[3][8]` (48 bytes of counts). Use the fixed R2.1 descriptor thresholds `T_CPU=3000`, `T_MEM=100`, `T_IO=500` bp, not mutable L1Core policy. For integer input x in 0..10000:

- bin 0: x = 0;
- bin 1: 0 < x < ceil(T/4);
- bin 2: ceil(T/4) <= x < ceil(T/2);
- bin 3: ceil(T/2) <= x < T;
- bin 4: T <= x < 2*T;
- bin 5: 2*T <= x < 4*T;
- bin 6: 4*T <= x < 8*T;
- bin 7: x >= 8*T.

Empty/unreachable bins are allowed for high T. Implement comparisons using sufficiently wide integers (no 16-bit `8*T` overflow). This quantizer describes stall-pressure history; it is not a prediction or threat score. Do not switch binning after testing without a new versioned protocol.

**Acceptance and time:** accepted samples must have `quality=L1_PQ_OK`, `observation.valid=true`, and each channel <=10000 bp. On first accepted sample, initialize monotonic cursor. Accept subsequent samples only if `monotonic_ms` is strictly increasing and at least **1000ms** after the last accepted sample. Equal/too-close time is skipped as ineligible; decreasing time must fail closed to an empty WARMING_UP model and report RESET. Explicit `L1_PQ_REGRESSED` or `L1_PQ_RESET` also resets perception memory. `ABSENT`, `INVALID`, `STALE`, unknown quality, false observation.valid and out-of-range values do not modify histograms or support; count bounded rejected samples if appropriate. Never let externally claimed invalidity modify protected core; only its original core input/time path remains authoritative.

**Observation support windows:** each valid accepted timestamp belongs to the integer bucket `floor(monotonic_ms / 300000)` (five-minute buckets). Increment `windows_seen` by **one** when the first accepted sample of a new bucket arrives, regardless of how many buckets were missed; do not infer fake independent samples from elapsed time. Count actual accepted observations separately. The state becomes SUPPORTED only after **>=256 accepted samples and >=4 observed buckets** since initialization; otherwise WARMING_UP. This is a support heuristic, not proof of statistical independence, calibration or causality. Do not treat these four buckets as four independent held-out anomaly *events*.

**Bounded forgetting:** increment the appropriate bin once per channel for each accepted sample. Before incrementing a channel if its 8-bin sum is >=1024, replace **every bin in that channel** with `floor(bin/2)` and increment a saturating channel-specific decay counter. Bins and totals must remain <=1024; lifetime accepted count and skipped count are saturating 32-bit values. Updates perform constant bounded work (3 x 8 bins); no heap, unbounded buffers, loops proportional to observation history or per-sample file operations. No hidden floating-point or stochastic online learning.

**Missing-data policy:** invalid or absent sample skips histogram updates. Explicit clock regression/reset wipes only the *new perception state*. No old core policy, state or shadow modification. Long gaps by themselves do not manufacture events; on resumption a valid timestamp may begin a new five-minute support bucket, and any future stale/large-gap policy must be frozen separately before changes.

**Restart freshness:** new clean `init` => WARMING_UP; restoring a validated persisted summary => `RESTORED_UNVERIFIED`, retaining historical counts but abstaining from future personalized novelty claims. Clear this status only after **128 new accepted samples spanning >=2 newly observed five-minute buckets** since import (keep these ephemeral refresh counters separate from lifetime support). This is not an authorization to classify anomalies; R2.2 returns no novelty at all.

**Proposed public functions** (freeze semantics before implementation): `l1_operational_memory_init`, `l1_operational_memory_step` (by-value observations and quality + monotonic time; changes ONLY provided memory), `l1_operational_memory_summary` (bounded read-only copy of model state and status), `l1_operational_memory_encode`, `l1_operational_memory_decode` (strict memory-to-buffer serialization, **not** filesystem I/O). Exact argument names can vary; outcomes and isolation must not.

## 4. Frozen separate V1 checkpoint layout

**Fixed serialized checkpoint exactly 80 bytes; little-endian; no ABI padding**. New magic ASCII `HMI_L1M1` (8 bytes), independent of existing 72-byte V2 core state. Offsets:

| Offset | Length | Field |
|---|---:|---|
| 0 | 8 | ASCII magic `HMI_L1M1` |
| 8 | 2 | version=1, unsigned LE |
| 10 | 2 | total_length=80, unsigned LE |
| 12 | 48 | 24 unsigned LE histogram bins, channel-major, 8 bins/channel |
| 60 | 4 | accepted_lifetime saturating uint32 LE |
| 64 | 2 | windows_seen saturating uint16 LE |
| 66 | 2 | reserved=0 |
| 68 | 4 | rejected_lifetime saturating uint32 LE |
| 72 | 4 | aggregate_decay_count saturating uint32 LE |
| 76 | 4 | IEEE reflected CRC32 LE over exact bytes 0..75, poly 0xEDB88320, init 0xFFFFFFFF, final xor 0xFFFFFFFF |

Decode must reject bad magic/version/length/CRC, nonzero reserved, any bin sum >1024, impossible support fields (accepted_lifetime less than a channel's bin sum, windows_seen > accepted_lifetime, empty histogram with positive accepted_lifetime) and truncated/oversized input. **On failure reset only perception memory to WARMING_UP**, never touch `L1Core`, `L1Shadow`, original core-state V1/V2 or other buffers. Encoding writes exactly 80 initialized bytes, with explicit bounds and no compiler-layout `memcpy`. CRC is accident/corruption detection, **not authentication, anti-replay or an authorization token**. Import does not copy a prior boot's monotonic clock into the runtime cursor.

New memory C struct, including runtime freshness counters, must remain **<=512 bytes**. The serialized 80-byte checkpoint is a separate object and does not change existing 72-byte core-state V2. Save/load to a guest file is not a runtime API in R2.2; tests may simulate reboot by passing an 80-byte snapshot between fresh in-memory instances.

## 5. Corpus first, learner second — hard immutable sequence

The parent R2.0 contract preregistered **40 sessions per synthetic machine**: first 24 train, next 8 calibration, final 8 untouched held-out; at least 256 rows/session. Fixed seeds A train=1101/calibrate=1201/heldout=1301, B=2101/2201/2301, shared_probe=9001, regime_swap=9002, faults=9003. Synthetic examples are machine-condition rhythms, **not actual owners, private traces, or user habits**.

**Before ANY `l1_operational_memory.c` implementation** make a distinct separate Git commit that contains: deterministic **stdlib-only** generator, precise engineered normal/anomaly event labels and episode boundaries; no overlap/leakage of training/calibration/held-out session row IDs; exact SHA-256 identities for all split files and probes, row/event counts and manifest; a verification utility that rebuilds identities; a static fixed comparator specification planned for R2.3. Use only deterministic integer/seeded arithmetic and no current host/user data. Confirm held-out >=20 positive and >=20 normal **independent scoring windows** per machine after exclusions; otherwise preregistered result is INSUFFICIENT_SUPPORT.

**Do not run/tune any learning model until that fixture+manifest commit is separately created and verified.** Do not read or optimize against held-out labels to revise algorithm or labels. All subsequent changes to generator/corpus after training begin require a new versioned study and reset of claimed preregistration. R2.2 uses train and calibration for engineering integrity checks only; **R2.3** performs precommitted independent usefulness scoring. No performance guarantee or particular learned difference is assumed from fixtures.

## 6. Required deterministic, adversarial, performance and historical tests

- Exact quantizer lower/equal/upper bounds for all 3 x 8 buckets, including unreachable high bins, 0, 10000, 10001. All invalid qualities and observation flags. No updating support on rejected input.
- Cold start, 255 vs 256 accepted samples, 3 vs 4 observed five-minute buckets, duplicate/too-close timestamp, backward time/reset, saturated counts, repeated halving/aging, long gaps, and change-of-regime adjustment. Verify mathematically expected individual bin counts before and after decay.
- Determinism: same history -> exactly same summary and serialized bytes. Different synthetic histories -> explainable differences in *summaries*, not presumed anomaly intelligence. Import/export -> exact 80B identity/normalized refresh semantics, corruption/overflow/truncation/extra bytes rejected, core unchanged.
- Strong integration isolation: for every test replay row compare **L1Action and all 104 bytes** of protected core with R2.2 memory present/absent, including invalid and regressed samples; shadow 208B observer-off equivalence when relevant. R2.1 classifier outputs unchanged, and no bridge into protected policy path.
- Build strict C11, NDEBUG, ASan/UBSan/leak, `make rc0-ci` and Debian `make rc0-qualification`. Existing RC0 source hash manifest, all historical scientific tests, held-out scores and frozen per-component RSS budgets must remain unchanged.
- Per incremental memory update: five optimized batches of >=10,000 calls. Candidate R2.0 memory/perception bound **median <=1000ns/sample and genuine individual-call p95 <=5000ns**, with a valid sampling method and no claim that batch-average quantiles are per-call p95. Report robust split microtiming for perception and combined perception+memory, VM/compiler sensitivity, process RSS <=8192 KiB; no new model state >512B. Any budget miss is NO_GO unless the protocol is revised before results.
- No private paths, credentials, user IDs, raw traces or hardware identifiers committed. No Windows host configuration, guest scheduler/cgroup/kernel/devices changes, OS actuation, actual user profiling, network services, or prolonged live PSI recording.
