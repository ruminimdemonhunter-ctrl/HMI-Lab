## 1. Objective, classification of success

**Research question:** Can the exact scientific training and evaluation harness detect invalid corpus/training states, erroneous five-hit rules, calibration lock divergence and false probe claims **before** an experiment is frozen or heldout data are opened?

`R2_3C_PREFLIGHT: PASS` requires every independent positive/negative known-answer gate below to pass. It means **harness integrity**, not novelty-detection usefulness, beneficial adaptation, machine individuality or resource optimization. `R2_UTILITY: UNDETERMINED`, `R2_INDIVIDUALITY: UNDETERMINED`, previous V1/V2 invalidity and historic NO_GO stay unchanged.

**No new 40-session corpus and no heldout scoring in this phase.** Once the preflight is independently reviewed, a *separate* freshly preregistered V3 study may be proposed, not automatically started.

## 2. Preservation and test inputs

Use the **existing merged** `L1OperationalMemory` API, with its true `L1_OM_MIN_SUPPORT_SAMPLES=256`, `L1_OM_MIN_SUPPORT_WINDOWS=4`, `L1_OM_WINDOW_MS=300000`, `L1_OM_SAMPLE_INTERVAL_MS=1000`, reset and restored-state semantics; never emulate the state machine using only counts. The original `L1Core` (104B), shadow (208B), R2.1 classifier, R2.2 112B operational memory, 80B R2.2 checkpoint, 72B legacy V2 state, source manifests, policies and historical tests are **unchanged**.

**One historical negative input** may be *read read-only* from the existing R2.3b V2 `machine_a_train.csv`, preferably fetched only by explicitly pinned PR #30 commit `b90cb1798d0f8cc9b2ef26f7aadb717f00dc02dd` with a checked SHA from existing immutable manifest. Other R2.3b training data may be inspected read-only for reproducibility; **never** use the V2 heldout CSV/episode labels to tune anything. No historical fixture may be copied/modified as a replacement corrected corpus.

All green control fixtures are tiny **test-only** deterministically constructed in-memory synthetic observations. They are NOT training/calibration/heldout data for a new novelty study, nor a validation of real workloads. No user data or live PSI collection.

## 3. Gate A — Actual support/state preflight (fixed test cases)

Implement a small offline state replay that calls `l1_operational_memory_init`, then `l1_operational_memory_step` for every row in original order, and derives **status and support from the actual returned struct**, including quality flags, invalid ranges, time gap eligibility, explicit RESET/REGRESSED and implicit decreasing monotonic timestamps. Emit a bounded deterministic report: `last_reset_row`, `last_reset_cause`, `post_reset_accepted`, `post_reset_distinct_observed_5min_buckets`, `final_status`, checkpoint hash if supported. Do not fabricate a window for each 5-minute interval missed; it counts only if a *valid accepted observation* was seen in that bucket.

**Fixed known-answer cases:**
- Cold start no samples => WARMING_UP, no supported reference.
- **Negative N1:** 256 spaced valid samples in only **three** distinct `timestamp_ms/300000` buckets => WARMING_UP.
- **Negative N2:** 255 spaced valid samples distributed over **four** observed buckets => WARMING_UP.
- **Positive P1:** exactly **256** valid accepted 1000ms-spaced samples, **64 samples in each of buckets 0, 1, 2, 3**, at `0..63000`, `300000..363000`, `600000..663000`, `900000..963000` => SUPPORTED, windows_seen=4, accepted_lifetime=256 (no resets).
- **Negative N3:** explicit RESET, explicit REGRESSED or an implicit monotonic regression *after the last third bucket* followed by only 256 accepted samples across 3 buckets => not SUPPORTED. Assert earlier counters reset and no stale support leaks. The regression event timestamp itself does not count as accepted.
- **Positive P2:** post-reset 256 accepted samples in four distinct observed buckets (same 64×4 construction using monotonically valid later timestamps) => SUPPORTED again.
- **Negative N4 / Positive P3:** corrupt 80B imported checkpoint is rejected and memory rewarms safely; valid import produces RESTORED_UNVERIFIED and cannot claim fully refreshed until 128 **new** accepted samples in >=2 newly observed buckets. No CRC/authentication or anti-replay claims.
- **Historical negative N5:** using pinned read-only V2 machine-A training file, assert unsupported after a late reset, including provenance of last reset around session 22 row 271; supported=FALSE with 3 post-reset observed buckets. If the input source is not available in branch workspace, test must be `NOT_RUN`, not silently replaced with synthetic P1 and called complete.

Strictly distinguish a `quality=INVALID` that temporarily marks status INVALID without erasing counters from a `quality=RESET` or REGRESSED that resets the whole new memory; do not conflate the two. Test stale, ABSENT, unknown quality, invalid numeric and out-of-order timestamp behavior.

## 4. Gate B — Novelty episode K and fair fixed comparisons

For testing **ONLY** define a typed candidate observation `EXPECTED | SUSPECTED | UNKNOWN` and a separate fixed comparator result. The R2.3b prospective science contract requires **novelty episode K=5** eligible row hits, *independent* of fixed comparator K. Implement a pure fixed-extent decision test helper with an explicit model kind so no generic `HighConfig.k` can override the novelty requirement.

- For >=10 eligible rows and zero, one, four hits => `EXPECTED` (novelty).
- For >=10 eligible and exactly five or six hits => `SUSPECTED` (novelty).
- For <10 eligible rows, ANY number of hits => `UNKNOWN`.
- For any `UNKNOWN` row whose excluded/invalidity makes eligibility inadequate, fail closed. Do not treat UNKNOWN as a true negative.
- Repeat novelty known answers while setting a *separate* fixed comparator K to each of `{1,3,5,8,12}`; novelty output must be identical. Include known-answer case where K=0 would previously turn all normal episodes positive; explicitly reject comparator K=0 as an invalid fixed configuration.
- Add an explicit **mutation/negative-control test** that deliberately reproduces the PR #30 K-selection bug and verifies that the new preflight catches it, rather than simply declaring a green test against the correct implementation.

These are **fixed-answer harness tests**, not training a new novelty model. No new L1 general intelligence outcome.

## 5. Gate C — Calibration lock must bind actual bytes and values

Using **small synthetic calibration-only fixtures**, design a standalone deterministic, bounded lock writer/verifier. SHA-256 every exact scorer, evaluator, tests and training/calibration fixture, plus split manifests; record tool/version, exact selected global novelty threshold, complete fixed baseline tuples and deterministic calibration-output hash. Verify selected tuple values lie inside the preregistered grids, all fields occur exactly once, all expected source/fixture files actually match, and rerunning calibration on the **same calibration fixtures** reproduces stored selected values and stdout/result digest. Include a complete **full-file SHA256** of lock content or a canonical fingerprint for accidental corruption detection.

Required invalid cases: absent lock, malformed/duplicate/unknown fields, changed source byte, changed CSV byte, changed score output, changed selected threshold (while syntactically in grid), wrong selection version, changed strongest-baseline identity, corpus manifest mismatch and corrupted lock fingerprint. A syntactically valid nonempty SHA field is **not** enough. Verify `no open heldout` using a supplied intentionally nonexistent/denied heldout path and/or file-open auditing; rejected locks must fail before any attempted heldout access.

A SHA digest/fingerprint without a trusted signature is integrity evidence only, **not authentication or anti-replay**. No production authorization may be inferred.

## 6. Gate D — Contextual probes require actual external truth

On tiny synthetic test-only probe data, supply independent `truth.csv` with two probes containing **identical observation/time bytes across both machines** and machine-conditioned expected outcomes:
- `A_NATIVE`: A EXPECTED, B SUSPECTED.
- `B_NATIVE`: A SUSPECTED, B EXPECTED.
- A quality-invalid probe: both UNKNOWN regardless of memory, with no core action change.

The harness must **load and compare truth** (not print `frozen_truth=external` or `actions_unchanged=YES` without evidence), validate schema, identities, row counts, support, per-episode hit logic, and require exactly matching prediction/truth for positive preflight. A control with swapped truth, missing probe, duplicated probe ID, distinct A/B input bytes, unsupported A/B reference, one erroneous decision and no valid row support MUST fail. No post-hoc truth inference from model outputs.

A passing **scripted fixture** validates comparison logic, not a real A/B novelty learner; test-only canned predictions must be clearly labeled and must never be counted as empirical model results.

## 7. Gate E — Independent metadata verifier and anti-coupling

Use a separate post-exclusion eligibility verifier with independent implementation and negative fixture that reproduces V1 declared pre-fault eligible count. Verify sample/episode identity, split/row/session uniqueness, recorded exclude_reason, quality, time and accepted support *separately*. A V2 corpus may be perfectly structurally valid but training-unusable; therefore **both** post-fault episode counts and *post-reset training SUPPORTED* status are mandatory prospective V3 pre-freeze gates. No rewriting, rehashing or relabeling old V1/V2 data.

Run protected action/104B core-byte and 208B shadow observer-on/off comparison across mixed samples and all new preflight operations; no path back into legacy priority, policy or OS control. Strict C11 (where C code is used), normal/NDEBUG, ASan/UBSan/leak, historical RC0 gates, frozen source audit; stdlib-only Python is permitted for an offline hash/CSV verification utility, no extra heavy runtime dependencies. All CI evidence must honestly distinguish harness normal/unit test from unexecuted real heldout study.

## 8. Release gates, measured output, and non-authorization

At end, publish `docs/L1-r2.3c-validation.md` with reviewed source SHA, explicit positive/negative test case matrix, exact reproduced V2 training negative, proof of no heldout access and no protected code changes, full CI and isolated Debian QEMU qualification. New preflight code is offline-only; where benchmarked report CPU/RSS and environment, but **do not claim system-level speed, savings or detection accuracy from harness tests**. New runtime perception/novelty module isn't being shipped in R2.3c.

**Preflight PASS only if A–E all verified including negative controls, source/lock binding and actual R2.2 memory support.** If any required case cannot run, `R2_3C_PREFLIGHT: NOT_RUN|FAIL` rather than GO. **PR stays draft and unmerged** until independent review and separate owner merge approval.
