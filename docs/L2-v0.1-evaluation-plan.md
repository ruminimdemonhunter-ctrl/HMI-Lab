# HMI L2 V0.1 — Frozen synthetic Adaptive Environment Engine engineering protocol

**PROTOCOL-FIRST COMMIT. NO V0.1 EXECUTABLE, FIXTURE CORPUS, PERFORMANCE RESULT OR HELD-OUT CLAIM EXISTS AT THIS COMMIT.**

- Approved parent: merged L2 V0.0 PR #34 on `main`, merge `9a0467d107903bde450d2e726bbe24d9ae426ba0`.
- Issue [#35](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/35); branch `feature/l2-v0.1-experience-core`.
- This protocol is for an **engineering proof of bounded experience representation**. It does not claim learning improves actual user experience. Historical L1 V0.x and R2 scientific verdicts remain frozen.

## 1. Objective and stop line

Two instances initialized with byte-identical L2 state must respond differently to the **same, explicit synthetic workspace query** after differing histories, with fully explainable learned role associations and routines. No hard-coded profession labels. The same invalid, missing-support, expired-context and denied-permission cases must abstain on every instance. Support must be demonstrated **after** resets, not inferred from nominal dataset length.

V0.1 includes fast context, slow work-role relationship graph and slow routine history, but **no actual OS user observation, filesystem access, proposal execution, or persistent user memory**. A text-only query result is a candidate logical layout, not a physical folder/template operation.

**Verdict separation:** `L2_V0_1_ENGINEERING=GO|NO_GO`, `L2_EXPERIENCE_STRUCTURE=DIVERGENT|NOT_DIVERGENT` are permitted. `L2_APPROPRIATE_INDIVIDUALITY=UNDETERMINED`, `L2_UTILITY=UNDETERMINED`, `L2_REAL_WORKFLOW_TRANSFER=NOT_TESTED`, `L2_OS_ACTUATION=NOT_AUTHORIZED` stay unchanged by any V0.1 test.

## 2. Wire schema and strict input grammar (freeze before code)

A finite ASCII CSV with **exact header**, no quoting/escaping/whitespace, exact 10 fields, LF newlines, max 256 bytes/line, max 100,000 event rows, max 16 MiB total:

```csv
schema,seq,monotonic_ms,quality,event,workspace,role,activity,l1_condition,provenance
```

- `schema = HMI_L2_EVENT_V1` on every row.
- `seq`: canonical unsigned decimal uint64, begins at 1, increases by exactly 1 per row including invalidity events; overflow invalid. `monotonic_ms`: canonical uint64, first >=0, **strictly increasing** on each valid row; regressions fail closed. Clock comes from fixture, never call a live system clock in the core.
- `quality`: `OK,ABSENT,INVALID,RESET`. In `ABSENT/INVALID`, no learning or confident context; record bounded invalid reason. Explicit `RESET` is allowed only on `event=RESET`, clears L2 volatile and slow identity, and requires newly sufficient sessions. Other combinations fail validation.
- `event`: `SESSION_BEGIN,SESSION_END,ROLE,CONTEXT,QUERY,GAP,RESET`.
- `workspace`: canonical number 0..4, with **0 reserved for no workspace**; role values are `NONE,CODE_EDIT,BUILD_TEST,DOC_VIEW,REFERENCES,CANVAS,ASSET_GROUP,EXPORT,OTHER`. No occupation/profile labels, strings identifying software, file names or personal content.
- `activity`: `NONE,IDLE,INTERACTIVE,BACKGROUND,MULTI_TASK,UNKNOWN`. `l1_condition`: `NONE,QUIET,CPU_PRESSURE,MEMORY_PRESSURE,IO_PRESSURE,MIXED_PRESSURE,UNKNOWN,UNRELIABLE`. Descriptors in V0.1 are **simulated copies** of descriptive categories, not live L1 or actual PSI measurements.
- `provenance=SIMULATED` exactly; any other source is rejected. No actual Windows/Debian observation source is permitted.

Allowed field placement, also part of the contract:
- `SESSION_BEGIN/END`: workspace 1..4; role NONE; activity NONE; l1_condition NONE.
- `ROLE`: workspace 1..4 matching open session; role !=NONE; activity NONE; l1_condition NONE.
- `CONTEXT`: workspace 0..4; role NONE; activity one of IDLE/INTERACTIVE/BACKGROUND/MULTI_TASK/UNKNOWN; l1_condition a descriptive enum excluding NONE.
- `QUERY`: workspace 1..4; role NONE; activity NONE; l1_condition NONE.
- `GAP`: workspace 0; role NONE; activity NONE; l1_condition NONE. Quality OK with explicit gap (a positive gap event may not be treated as learning evidence).
- `RESET`: workspace 0; all other payloads NONE; quality RESET.

A malformed/bad-quality `ROLE` never contributes a node/edge/routine. **No partial session commit**: an invalid/gap/reset/sequence/time error during an open session aborts that session and discards its pending roles. Failed input cannot create training evidence, a proposal, or a partially updated durable graph. Parser failures return explicit error status; no undefined behavior, trusted arbitrary strings, or shell execution.

## 3. Fast context state machine

Fast `L2Context` enum: `UNKNOWN,IDLE,FOCUSED,MULTI_TASK,BACKGROUND_BUSY,RESOURCE_CONSTRAINED,TRANSITION`.

A valid `CONTEXT` row maps by this exact priority:
1. missing/invalid provenance, quality, time or `l1_condition` UNKNOWN/UNRELIABLE, or `activity` UNKNOWN -> UNKNOWN.
2. any `l1_condition` CPU_PRESSURE/MEMORY_PRESSURE/IO_PRESSURE/MIXED_PRESSURE -> RESOURCE_CONSTRAINED; **never downgrades L1 memory/OS safety**.
3. `l1_condition=QUIET`: activity IDLE->IDLE, INTERACTIVE->FOCUSED, BACKGROUND->BACKGROUND_BUSY, MULTI_TASK->MULTI_TASK.
4. `GAP`, implicit delta between adjacent **valid observed event timestamps** >60,000 ms, session abort due invalid input -> UNKNOWN/TRANSITION; require a new valid `CONTEXT` before any candidate query is allowed.
5. `RESET` clears context, session and slow memory; never restores previous support from older observations.

Context freshness for queries: latest accepted `CONTEXT` must be <=60,000 ms old, provenance SIMULATED, quality OK; if not, return NONE/UNKNOWN with reason `STALE_CONTEXT`. A query **never trains**. A `SESSION_BEGIN` after invalid quality starts clean only when new valid input is explicitly supplied.

Input invalidity cannot make a confident claim: all unrecognized enums, large fields, negative values, duplicate sequence, overflow, malformed CSV, resets and stale descriptors fail closed.

## 4. Slow operational experience model — fixed arrays, no heap

Model is a single caller-owned fixed-width C11 state, total `sizeof(L2State)<=8192` bytes:
- **workspace identifiers** exactly 1..4, with per-workspace `completed_sessions` and `accepted_transitions` saturating uint16 counts.
- at most **16 `(workspace, role)` association nodes** with saturating uint16 counts and `last_completed_session_generation`.
- at most **32 directed edges** `(workspace, from_role, to_role)`, each with uint16 count and last-seen generation.
- at most **16 ordered three-role routine triples** `(workspace, r1, r2, r3)`, each with saturating uint16 count and last-seen generation.
- volatile pending session: at most **8 roles**, current workspace, session status; events over that per-session capacity invalidate/abort, not silently truncate.
- no dynamically allocated strings, raw OS identifiers, timestamps of user activity, filenames, filesystem paths or persistence. Serialization/checkpointing **not in V0.1**.

A `SESSION_BEGIN` opens exactly one workspace. Each valid `ROLE` appends to the bounded pending sequence, but does not immediately modify stable node/edge/triple state. A matching valid `SESSION_END` with **>=3 role observations** commits atomically:
1. increment per-workspace `completed_sessions` by 1;
2. increment node `(workspace,role)` counts **once per role occurrence**;
3. increment each adjacent directed pair (N-1) in that session and `accepted_transitions` by N-1;
4. increment each consecutive ordered triple (N-2);
5. increment global `completed_session_generation` once.

All counts saturate at UINT16_MAX. For a full node/edge/triple table, deterministically evict **lowest count**, then oldest last-seen generation, then lexicographically lowest tuple; replacement starts count at 1. Numeric tuple order uses ascending workspace and ascending role-enum IDs. **No unbounded loops**: operate only within frozen capacities. Every 16 completed eligible sessions, apply deterministic aging by integer-halving all association/edge/triple counts and per-workspace support counters, discard zero-count entries. This is a prospective heuristic and is **not** evidence of scientific benefit.

Per-workspace candidate eligibility requires simultaneously:
- at least **3 completed eligible sessions since the most recent full reset**, and
- at least **6 accepted directed role transitions in that workspace**, and
- at least one ordered triple for that workspace with count >=2.
If unsupported, query returns `NONE/WARMING_UP`. A cold-start/history split may never fabricate support by skipping bucket/sample constraints.

## 5. Text-only query output — model identity, not a filesystem proposal

`QUERY` for a workspace returns an immutable result with status `NONE|CANDIDATE|BLOCKED`, context enum, workspace ID, evidence counters, three ordered **role-enum codes** and reason enum. **No raw prose with arbitrary user text and no executable command/path**; human-readable descriptions belong to the offline renderer, not action authority.

If input invalid, denied provenance, unsupported, stale context or pressure-safety conflict => `NONE` or `BLOCKED` with explanation; no candidate. For a supported workspace with good fresh context and no RESOURCE_CONSTRAINED condition:
- enumerate ordered triple entries for that workspace with count>=2;
- choose largest triple count; tie -> lexicographically lowest ordered triple tuple;
- return `CANDIDATE` with the chosen role triple, graph/transition/session evidence and `requires_user_approval=true`.
This algorithm is intentionally simple; it **cannot create folders, open applications, change layouts or approve its own suggestions**. It makes no claim that the candidate is beneficial or even well-liked by any real user.

No manual explicit user profile, role-to-occupation map or hard-coded `if programmer ->...` condition. Workspace=1 is a *synthetic opaque local handle*, not a person's identity.

## 6. Frozen known-answer engineering histories and independent fixtures

Start byte-identical empty states and use equal event schemas, quality/sequence/time cadence:
- `A`: workspace=1, **4 complete sessions**, each role sequence `CODE_EDIT,BUILD_TEST,DOC_VIEW`, each session with fresh `CONTEXT(INTERACTIVE,QUIET)`; a final fresh identical `QUERY(workspace=1)`. Expected supported candidate triple `CODE_EDIT|BUILD_TEST|DOC_VIEW`.
- `B`: workspace=1, **4 complete sessions**, each `REFERENCES,CANVAS,ASSET_GROUP,EXPORT`, with the same valid context cadence and final identical `QUERY`. Expected supported candidate `REFERENCES|CANVAS|ASSET_GROUP` (lexicographic tie versus the adjacent other triple).
- `MIXED`: same machine with 3 sessions of A's sequence in workspace=1 and 3 sessions of B's sequence in workspace=2; independent queries must preserve both workspace-specific triple candidates. Never assign a global "career".
- `COLD`: a single complete session, query => `NONE/WARMING_UP`; one valid `CONTEXT` without any session also unsupported.
- `NEGATIVE`: a late `RESET` followed by only 2 complete sessions and a query => `NONE/WARMING_UP`; `GAP`, invalid quality, timestamp/sequence regression, duplicate role/event, >8 pending roles, missing `SESSION_END`, bad provenance, oversized input and stale `CONTEXT` may not produce a candidate. Query on RESOURCE_CONSTRAINED => `BLOCKED` with zero action.
- `COMMON_SAFE`: A and B must generate identical BLOCKED/NONE behavior on the same invalid and pressure-conflict queries, regardless of different remembered triples.
- Stress deterministic saturating counts, capacity eviction, 16-session aging, reset, restart (empty memory), and 100,000-row synthetic finite playback without heap growth.

**Independent expectation:** a separate fixture verifier derives expected successful session/transition/triple counts, uniqueness, post-invalid eligibility and reset support from the event log, not from the model's own reported counters. Every negative fixture must have a known failing mutation of the verifier. The test must not read actual host activity or synthetic held-out utility labels.

## 8. Safety and non-authorization

- Never change original `L1Core`, shadow, legacy V2 policy state, R2.1/R2.2, R2.3c, priority/security rules, or historical judgment. L1 remains authoritative for its published safety behavior; L2 cannot call it to change policy.
- V0.1 must not read live process names, windows, keyboard, folders/files, user content, credentials, actual PSI or network. No shell/OS command authority, file move/rename, cgroup/scheduler write, service install, host configuration, privilege elevation, background task, L3 agent or API service.
- Only explicit offline *synthetic* C11 test/CLI inside isolated Debian QEMU. Windows source edits via the normal development workflow are fine; **do not run the L2 executable against Windows/host OS**.
- File organization remains hypothetical role-enum **virtual organization suggestion**, never a real path.
- No claims of "personalization GO", consciousness, user identity inference, real workload efficiency or OS actuation from engineered A/B differentiation.
- Physical/device changes and real user observation need separate opt-in, privacy scope, reversible capability broker and human authorization.
