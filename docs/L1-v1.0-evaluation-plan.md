# HMI L1 V1.0 — preregistered real PSI evidence protocol

**Status: frozen for implementation planning, before new V1.0 offline analyzer code, before any new long real PSI capture or held-out analysis.**

**Base:** merged V0.9 main `2d05ceb33a27efdfd1de76da4041e74ba62aab87`. **Issue:** [#15](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/15). **Parent stabilization plan:** [#13](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/13).

## Question and epistemic limits

Can the unchanged bounded L1 shadow forecaster obtain sufficiently valid, *genuinely observed* forward-pressure feedback from Debian PSI recordings to permit an honest per-class static-versus-adaptive comparison? The second question is whether forecast boundary changes increase or decrease errors and missed positives in the test segment. L1 is not authorized to act on these forecasts. The goal is **evidence readiness**, not an automatically successful adaptive algorithm. No hardware or OS resource savings have been demonstrated.

Historical decisions, documentation and checksum identities are immutable: V0.4/V0.5 adaptive actuation NO-GO; V0.6 SHADOW_PREDICTION NO_GO, ACTION_COUPLING NO_GO; V0.7 DIAGNOSTICS NO_GO; V0.8 RECORDER_EFFICIENCY GO under its frozen benchmark and REAL_EVIDENCE INSUFFICIENT; V0.9 REPLAY_READY GO only as read-only inspection; REAL_RESOURCE_BENEFIT NOT_ESTABLISHED.

## Boundaries

- Do **not modify** `l1_step_at()`, `l1_shadow_step_at()`, safety priority memory > I/O > CPU > HOLD, policy validity/bounds, state recovery, V1 migration, 72-byte V2 encoding, historical synthetic evaluations or held-out identities.
- One explicit unprivileged, finite, **read-only** process in the Debian QEMU guest. The offline CLI reads validated, already-existing `HMI_L1_PSI_TRACE_V1` files. No source writes, operating-system actuation, scheduler/cgroup controls, PSI trigger registration, device/firmware/hardware operations, service, network requests, telemetry upload, credentials, Windows host access, L2 or L3.
- User's real recording is sensitive even without identity fields. Never commit, attach, sync or print its path/raw rows by default. Guest-local `/home/lab/hmi/data` remains outside synchronized `/home/lab/hmi/src`.
- **Research-length recording gate:** explicitly authorize **both** finite duration and exact guest-local output path in a separate user instruction. The branch, issue, this document or generic “go ahead” do NOT start the recorder. No automatic stress workload.
- All scientific criteria are frozen before code. If an algorithm, threshold, split, score definition or criterion is changed after observing results, that constitutes a new preregistered experiment, not a V1.0 fix.

## Data and provenance

- Parse full V1 file with strict version/fields, checksum, footer, units and continuity requirements. At most 86,400 samples, 16,777,216 bytes, 512 bytes/line and existing recorder cadence bounds.
- Validate entire file before declaring `verified`. Replay without trusting earlier metadata; compare checksums, byte and row counts, file identity and timestamps. Clearly disclose that FNV-1a and inode/mtime are not cryptographic authenticity or a malicious-writer defense.
- For each real session document outside the trace: V1 checksum, samples/size/permission, chosen finite duration/cadence, recorder commit, guest kernel/compiler, missing samples, invalid/gap/reset counts, whether pre-existing external workload is known, and whether the user explicitly authorized the capture. Never infer load cause or synthetic event truth.
- Every source of evaluation is tagged `synthetic-fixture`, `synthetic-historical`, or `real-guest-v1`. Fixtures validate code; historical synthetic held-out reports remain immutable. A five-sample smoke cannot establish future forecast skill.

## Split, forward outcomes and comparison

- Partition **by relative monotonic time**: development = first 60% of recording, followed by a >=65,000ms embargo; evaluation = all samples after embargo. No forecast crossing a split boundary is scored. The 60,000ms outcome horizon and 60,000..65,000ms feedback endpoint interval, and >5,000ms intersample gap rejection remain as the V0.6 shadow defines them.
- Reinitialize independent L1 shadow and fixed-comparator state at the start of evaluation; do not carry adaptation, feedback or pending windows from development. Label warm-up effects and learning eligibility clearly. Do not tune thresholds, choose windows or fit a model using evaluation outcomes. Existing L1 learner time/sample gate remains 600 valid samples and 600,000ms.
- Treat CPU some, memory full, and I/O full cumulative stall microseconds as **observational forward-pressure proxies**, not latent event or control-outcome truth. Continue using V0.6 outcome thresholds: CPU some 800bp, memory full 40bp, I/O full 150bp.
- Two separately labeled predictor initializations: `live-default=800/40/150` and `v06-trained=2000/75/600`, each static versus the **unchanged** outcome-aware shadow learner. Never transfer reported scores between configurations.
- At issuance pair static and adaptive binary predictions with their same future observed outcome, and score only when it arrives validly. Count eligible/missing by exact reason, unfinished forecasts, and paired changed-forecast opportunity and correctness. Keep published actions and shadow forecasts separate, with byte-for-byte `L1Core` and `L1Action` equivalence between accompanied and reference steps.
- Report for each configuration and class: issued/eligible/scored count, TP/TN/FP/FN, positive prevalence, recall/missed positives, false alarms, specificity, precision, binary Brier and per-class change/harm; offset updates, saturation, scoreable changed-forecast count and time-to-first-material-change. No ratio on empty denominator; print `N/A`. Aggregate scores never conceal class-specific regressions or positive scarcity.

## Independent unit and scientific gates

**Evidence readiness gate** is separate from skill:

1. A real explicit-capture trace is fully valid, attributed and locally sealed, and the required temporal split has no leaked model state or overlapping forecast.
2. The held-out **evaluation segment** contains >=30 eligible **non-overlapping scored** 60-second windows (not 30 samples). At least 80% of issued forecasts are eligible for feedback. Each class has >=5 positive AND >=5 negative scored outcomes before making a substantive class-level skill claim; otherwise that class is labeled underpopulated, and overall `REAL_EVIDENCE_READY` fails.
3. Class-specific confusion identities, lost-feedback reasons and paired disagreement accounting reconcile exactly; output distinguishes data quality from forecast skill.
4. Core-state/action equivalence and safety/fallback invariants pass with all earlier frozen identities and state encoding intact.
5. Optimized offline analyzer RSS <=16,384 KiB on maximal valid input and bounded emitted output; deterministic full fixture, rejection, sanitizer and CI tests all pass.
6. Privacy audit: no raw real trace committed, uploaded, emitted in CI or redirected to unapproved files; no control interfaces.

Return **`REAL_EVIDENCE_READY`** if all pass; otherwise **`REAL_EVIDENCE_INSUFFICIENT`** with failed gates and counts. Readiness never overrides `ADAPTATION: NO_GO` or `ACTION_COUPLING: NO_GO`. `FORECAST_TRANSFER` is `UNDETERMINED` until appropriately supported observations and separate preregistered criteria; do not manufacture p-values from highly correlated windows. Distinct captured sessions (each separately authorized and preplanned) are better independent units than windows in a single time series.

**Example feasibility, not approval:** a continuous 120-minute recording with 1,000ms cadence has ~7,201 samples. First 72 minutes are development; after 65s embargo, ~46 complete 60s evaluation windows are *theoretically* possible, before missing data, failed feedback or insufficient class prevalence. Suggested later opt-in path: `/home/lab/hmi/data/v10-session-01.l1trace`. No duration/path is selected on the user's behalf.
