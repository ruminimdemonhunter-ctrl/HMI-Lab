# HMI Level 1 v0.3 validation report

Date: 2026-10-22

Scope: memory stability and deterministic experimental intelligence. Level 1
remains a native C11, unprivileged, read-only resource recommendation engine.

## Implemented changes

- Replaced call-count-only adaptation with an explicit monotonic-time API.
  Adaptation requires at least 600 valid samples and at least 600,000 elapsed
  monotonic milliseconds. A regressing timestamp fails closed to `HOLD` and is
  not counted. Policy replacement/rollback and state recovery restart the gate.
- Replaced libc-dependent test assertions with unconditional failure checks and
  added a complete `-DNDEBUG` test build.
- Restricted benchmark counts to 1..1,000,000,000 core samples or
  1..1,000,000 live samples and rejected signs, suffixes, zero, overflow, bad
  modes, and out-of-range values.
- Added the strictly versioned 64-byte local state format, CRC32, mode-0600
  same-directory temporary files, file/directory `fsync`, atomic rename,
  rollback snapshot persistence, and safe-default recovery.
- Added a predeclared deterministic replay comparing fixed behavior memory with
  the same core under bounded adaptation.
- Added GitHub Actions jobs for strict C11 build/tests, `-DNDEBUG`, deterministic
  replay acceptance, AddressSanitizer, UndefinedBehaviorSanitizer, and leaks.
- Added LF checkout rules after the Windows-to-Debian run exposed CRLF in the
  previously tracked benchmark shell script.

No L2/L3 service, scheduler, cgroup, priority, kernel, device, firmware, QEMU,
or hardware-control write was added. The optional state file is local behavior
memory, not resource actuation; without `--state`, the monitor performs no local
state persistence.

## Debian QEMU validation

Environment: Debian GNU/Linux 13.7 (trixie), kernel
`6.12.113+deb13-amd64`, x86-64, Debian GCC/cc 14.2.0-19.

Reproduction from Windows PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync-source.ps1
ssh -p 2222 lab@127.0.0.1 "cd /home/lab/hmi/src/level1 && make clean all test"
ssh -p 2222 lab@127.0.0.1 "cd /home/lab/hmi/src/level1 && make test-ndebug && ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 make sanitize"
ssh -p 2222 lab@127.0.0.1 "cd /home/lab/hmi/src/level1 && make clean all && sh ./run_replays.sh 5 10000 && sh ./run_benchmarks.sh 5 10000 10000000"
```

The following passed without compiler warnings:

- optimized `make clean all test`;
- all prior policy, safety, rollback, PSI, and 23 trace decisions;
- high-frequency time-gate bypass rejection, monotonic regression fallback,
  `0 -> 1 -> 2 -> 2` saturation, and stable one-step decrease;
- state round-trip, CRC corruption, truncation, trailing data, permissions,
  atomic replacement, missing path, rollback recovery, and safe defaults;
- benchmark argument grammar, overflow, mode, and limit tests;
- complete test suite compiled with `-DNDEBUG`;
- AddressSanitizer, UndefinedBehaviorSanitizer, and leak detection;
- final optimized rebuild and test.

The monitor created a 64-byte mode-0600 state as user `lab`, then a fresh
process recovered generation 1 and remained at `HOLD`. The scoped temporary
state was removed after the test.

## Deterministic replay result

The 1,240-sample, one-second trace declares `HOLD` as truth during two noisy
regions, followed by one 30-sample sustained CPU-pressure event. The initial
noise supplies the predeclared evidence for one bounded debounce increment. In
the fixed-memory control, a constant nondecreasing timestamp prevents the time
gate from elapsing while leaving decision logic unchanged.

| Metric | Fixed memory | Bounded adaptive |
|---|---:|---:|
| False-positive samples | 513 | 307 |
| Missed-response samples | 2 | 3 |
| Decision oscillations | 292 | 154 |
| Mean/max detection delay | 2 / 2 samples | 3 / 3 samples |
| Final debounce increment | 0 | 1 |
| `sizeof(L1Core)` | 88 bytes | 88 bytes |
| Peak replay-process RSS | 1,524 KiB | 1,524 KiB |

Across five independent processes, each replaying the trace 10,000 times, fixed
CPU cost ranged 21.873-36.214 ns/decision (median 30.100); adaptive cost ranged
24.802-33.198 ns/decision (median 28.416). The ranges overlap and ordering
changed in earlier runs, so no CPU-speed improvement is claimed.

Replay RSS is one process-wide peak measured after both engines run; the shared
1,524 KiB value cannot attribute pages to either engine independently.

On this declared trace only, bounded adaptation reduced false-positive samples
by 206 (40.2%) and oscillations by 138 (47.3%), while adding one missed sample
and one sample of detection delay. This is a deterministic heuristic tradeoff,
not generalization, training, causal workload improvement, or learned optimality.

## Observation-to-decision overhead

Five independent runs used 10,000,000 core decisions and 10,000 live Linux PSI
observations per engine. All 100,000 live observations were valid.

| Metric | Fixed | L1 v0.3 |
|---|---:|---:|
| Core ns/decision, median | 3.199 | 18.813 |
| Core ns/decision, range | 3.043-3.746 | 17.336-20.506 |
| Live CPU ns/sample, median | 138,617.360 | 137,213.170 |
| Live CPU ns/sample, range | 118,603.290-140,864.240 | 130,901.360-143,550.190 |
| Peak RSS median | 1,408 KiB | 1,408 KiB |
| Peak RSS range | 1,408-1,412 KiB | 1,408-1,464 KiB |

Median live wall time was 1.387089 seconds fixed and 1.373926 seconds L1. PSI
read/parse cost dominated the 15.614 ns median incremental core cost, live ranges
overlapped, processes ran sequentially in fixed order, and all live decisions
were `HOLD`. No live performance advantage is established.

## Scientific and security limitations

The replay is one hand-authored synthetic distribution whose noise burst length
was chosen to expose debounce behavior. Its acceptance criteria were declared in
code, but it is not an independent dataset and cannot establish intelligence in
new environments. “Improvement” means fewer mismatches and transitions against
that trace's labels, with a measured detection-delay cost.

CRC32 detects accidents, not malicious replacement. State and proposal files
remain unauthenticated; rollback depth is one; persistence is single-writer and
Linux-local; power-loss guarantees depend on the filesystem/storage stack.
There is no remote update service. An attacker with file or process-memory access
is outside the current boundary.

GitHub-hosted CI complements but does not replace the Debian QEMU result. Timing,
RSS, and PSI values depend on VM/host load and are descriptive, not confidence
intervals. No resource outcome, energy saving, user benefit, or scheduling
improvement was measured because Level 1 still has no actuator.
