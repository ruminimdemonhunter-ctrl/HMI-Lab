## V0.0 deliverable
A human-reviewed design agreement for a local, deterministic, low-memory OS-context **observer**. It should help the computer describe coarse situations and gradually accumulate bounded experience without claiming to infer personal intent from pressure data. It must not change the Windows host or create a new OS controller, daemon, telemetry service or kernel component.

## Suggested V0.1 branch, *only after separate approval*
`feature/l2-v0.1-offline-context`, forked from accepted main **after** V0.0 docs are reviewed/merged if authorized.

### Ordered steps
1. Create a new issue and preregister the exact V0.1 `L2EventV1` schema and deterministic event state machine **before** implementation. Classify activity hints and descriptive L1 conditions as **synthetic input**, not actual user activity or directly sensed pressure.
2. Freeze finite input sizes, monotonic/sequence freshness rules, support/abstention state, L2 state size, output schema, reason codes, and fixed candidate resource budgets. Negative tests and constraints are part of the freeze, not added after failures.
3. Build synthetic corpus and **independent** verifier first; run prefreeze support/eligibility simulation through proposed state engine so we avoid R2.3b's unusable-history failure. Commit generator, SHA identities, and verifier **before** the implementation code.
4. Implement only pure C11 finite context transitions `UNKNOWN/IDLE/INTERACTIVE/BACKGROUND_BUSY/RESOURCE_CONSTRAINED/MIXED/TRANSITIONING`. Prefer a tiny CLI that reads explicit local synthetic fixture input and prints bounded, non-sensitive summaries. No per-event heap, process scan, network access, timers, telemetry sampler or OS write.
5. Verify exact L1 104B core and 208B shadow byte/action equivalence with L2 observing synthetic copies. Guard unknown enum, stale data, divergent timestamps, reset, overflow, malformed CSV, invented confidence and contradictory context.
6. Run strict normal, NDEBUG, sanitizer/leak/RC0 historical regression and source-hash audits, then isolated Debian QEMU resource qualification. Publish a complete report and leave future PR draft/unmerged for independent review.
7. **STOP** before real sensing, background operation, OS changes, a production policy proposal bridge, any learning-enabled actuation, L3 service, or a live guest study. Those require separate human scope and written authorization.
