## Mission: a locally evolving OS environment, not another PSI detector

V0.1 must contain a small but real **experience representation**:
- Fast deterministic context from explicit synthetic events.
- Slow fixed-size workspace/tool-role association graph and routine-transition counters.
- A pure in-memory query reporting learned modes/relations and proposing a **text-only** workspace-start layout candidate when support exists.
- Cautious UNKNOWN/NONE output for new history, mixed signals, invalid provenance and unsafe conditions.

The desired engineering demonstration:
- Two empty states start byte-identical.
- Synthetic device A repeatedly transitions CODE_EDIT -> BUILD_TEST -> DOC_VIEW.
- Synthetic device B repeatedly transitions REFERENCES -> CANVAS -> ASSET_GROUP -> EXPORT.
- Both receive the same neutral `PROPOSE_WORKSPACE_START` request; supported states expose explainable, different preferred **candidate** virtual layouts.
- A mixed-history device must retain more than one supported mode or abstain rather than assert a fixed profession.
- Safety/invalid/permission-denied events are treated identically and conservatively on both machines.

Do not use literal `programmer` or `artist` labels as predictor inputs. Do not call this engineering state divergence empirically correct personalization.

## Mandatory pre-implementation decisions in V0.1 first commit

Create a new V0.1 issue/branch **only after separate acceptance of this V0.0 draft**. Commit a frozen V0.1 plan before generator or C code with:
- Exact bounded `L2EventV1` wire/text grammar, valid enums and sizes; all data synthetic and unidentifying.
- Short context state machine: quality, precedence, TTL, reset, support and reason codes.
- Slow graph/routine model fields and byte layout; max nodes, edges, modes, transition counters, update/decay, no event-loop allocation.
- Typed read-only `L2SnapshotV1`, `L2CandidateHintV1`, and `l2_init`, `l2_step_event`, `l2_snapshot`, `l2_query_workspace_start` calls. Candidate output is text/category IDs **without executable commands**.
- Support thresholds **appropriate to simulated workflows** (NOT borrowed from R2.2). Explicit post-reset preflight so neither A nor B can become an unsupported training reference after data freeze.
- Strict prospective limits (initial architecture targets: <=8KiB L2 state, <=8MiB analyzer RSS, 50us median and 250us measured p95 per event), finite replay sizes, accepted clock methodology and fail-closed behavior.
- Test fixture truth origin, frozen known answers, negative controls and independent verifier. No retroactive fixes after held-out exposure.

## Ordered V0.1 engineering stages (future, not yet performed)

### A — Synthetic fixture first
1. Generator and independent validator (stdlib-only tooling acceptable). Keep A/B device events distinct, deterministic, support-adequate, with explicit reset/quality faults and a third mixed-history control.
2. Verify post-exclusion counts, sequence/time, replay eligibility, required states from the **exact design state machine**, input ID/hashes and negative fault fixtures *before committing immutable data*.
3. Commit SHA manifest and fixture provenance separately before any algorithm code. Small known-answer engineering traces are enough; no expensive V3-style corpus.

### B — Pure implementation
4. Implement `src/level2/` separate from `src/level1/`, C11 fixed arrays, no per-event heap/network/timer/system process scans. Offline CLI should consume only specified synthetic fixtures in the Debian QEMU guest.
5. Keep work-context and long-term associative/routine memory separate, with saturating counters, explicit ageing and support/abstain semantics.
6. Output bounded aggregate explanations: e.g. `MODE=CODE_EDIT|BUILD_TEST`, `SUPPORT=...`, `CANDIDATE=VIRTUAL_TEMPLATE_DEV` or `NONE`. This is never applied to files.

### C — Security, tests and qualification
7. Test time/sequence regression, reset close to corpus end, mixed-mode ambiguity, full node/edge capacity, invalid enum, big input, stale L1 descriptor, repeated/deduped event, corrupted snapshot (if any), contradictory sources, no hidden user identity, source audit and denied filesystem/write attempted hooks.
8. Run normal/NDEBUG/ASan/UBSan/leak with strict C11, existing `make rc0-ci` and `make rc0-qualification`; verify protected L1 action/core/shadow on/off bit-for-bit and previous invalid scientific outcomes unchanged.
9. Optimize resource use only within frozen bounds. Log process RSS separately from model bytes and honestly disclose VM jitter, per-call p95 and limitations.
10. Report `L2_V0_1_ENGINEERING: GO|NO_GO` and `L2_EXPERIENCE_STRUCTURE: DIVERGENT|NOT_DIVERGENT`. Even DIVERGENT does not equal beneficial individuality or real-world learning success. Leave V0.1 PR draft/unmerged for independent review.

### D — STOP
No real process/file/window/keyboard monitoring, actual filesystem organization, moving/renaming, OS service registration, guest actuation, Windows host changes, L1 policy writing, auto approval, L3/cloud actions or raw personal-data storage. Those require separate authorization and review.
