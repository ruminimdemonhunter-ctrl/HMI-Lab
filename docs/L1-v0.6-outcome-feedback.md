# HMI Level 1 v0.6 outcome-feedback design

V0.6 adds a read-only shadow forecaster beside the existing V0.5 recommendation
core. It does not change `l1_step_at()`, `L1Core`, policy validation, action
priority, confirmation behavior, or the 72-byte V2 persistent-state format.

## Data boundaries

The Linux adapter reads the existing CPU `some`, memory `full`, and I/O `full`
PSI lines. The legacy `avg10` parser and observation API remain available. A new
combined API additionally parses each line's cumulative `total` microseconds.
All filesystem and clock access remains in the Linux adapter and monitor.

The deterministic shadow component receives only explicit values:

1. the current `avg10` observation;
2. current cumulative PSI counters;
3. caller-supplied monotonic milliseconds.

It freezes one three-class prediction, waits for the non-overlapping 60-second
window, and only then derives observable feedback from counter differences. It
never receives synthetic latent truth, an evaluator grade, future samples, or
held-out results. Evaluator truth is a separate offline structure used only for
action scoring and lead-time interpretation.

## Fixed-capacity learner

`L1Shadow` has no pointers, allocation, locks, files, clocks, syscalls, or
logging. It stores one pending forecast, counter endpoints, three signed offsets
in `[-2,+2]`, and fixed-width saturating evidence/statistics. CPU, memory, and
I/O update independently after at least 600 valid samples, 600,000 monotonic
milliseconds, and eight completed windows.

Miss-dominant feedback lowers a forecast threshold one step; false-alarm-
dominant feedback raises it one step. Ambiguous evidence leaves it unchanged.
Invalid windows are discarded. Timestamp regression, counter decrease, or an
impossible delta returns offsets and evidence to neutral. No result from the
shadow API is accepted by `l1_step_at()`.

The live monitor calls the V0.5 core and shadow component separately. It prints
the core action plus explicitly labeled shadow diagnostics. Tests run duplicate
V0.5 cores on identical samples and verify byte-identical core state and actions
while only one stream executes shadow feedback.

## Persistence and authority

Outcome evidence is transient. `l1_state.c` remains unchanged: V1 migration and
V2 encoding, CRC, atomic replacement, bounds, and safe recovery retain their
V0.5 contract. Restart begins shadow learning from neutral.

The only operating-system input is read-only `/proc/pressure` telemetry. V0.6
adds no scheduler, cgroup, process-priority, kernel, device, firmware, network,
or hardware-control interface. Shadow forecasts are not actions and do not
authorize actuation.
