# HMI L1 V1.1 — frozen test-only behavior-memory proposal-boundary protocol

**Status: FROZEN before V1.1 implementation, adversarial tests or benchmark selection.**

Base: merged V1.0 `599c08c2203af72806a1594b5750a37f6bf49a66`. Work item: [#17](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/17); stabilization contract: [#13](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/13).

## Intent

Preserve the original architecture: tiny deterministic L1 C11 engine and compiled safety rules, strictly bounded behavior memory, future L2 proposes bounded policies, and L3 cannot write L1. This milestone is a **test-only proposal contract**, never a deployed authorization service. A test-only GO proves bounded parsing and fail-closed rejection, **not** identity authentication, durable anti-replay, or permission for L2 to change a running L1.

### Existing code invariants, examined at V1.0 base

- `L1Policy`: `schema_version` uint32, `generation` uint32, CPU/memory/I/O basis-point thresholds uint16, `confirmation_samples` uint8.
- `l1_policy_valid` enforces schema v1, generation >0, CPU 500..8000, memory 25..3000, I/O 100..5000, confirmations 2..10.
- `l1_apply_policy` requires proposal generation **strictly greater** than current and resets action/candidates/temporary adaptive state to HOLD on acceptance; invalid proposals do not mutate L1 state. `l1_rollback_policy` uses a fresh, strictly greater generation.
- `l1_read_policy(path)` + `l1_main --policy` are **legacy untrusted development interfaces**, not authenticated future L2. They do not verify author or protected key. Production L2 MUST NOT be claimed secure while this legacy path remains an unrestricted live bypass.
- `l1_state_load` validates CRC and defaults to HOLD on failure, and V2 persistence is **exactly 72 bytes**. CRC detects accidental corruption only; user/attacker who can rewrite state storage can replay earlier authenticated-looking state without a separate protected monotonic trust store. Do not claim recovery authentication or robust anti-rollback.
- Compiled action priority remains memory > I/O > CPU > HOLD, fixed hysteresis and fallback/confirmation boundaries. Core size 104B, shadow 208B; `l1_shadow_step_at()` never changes published action. All V0.4–V1.0 checksums and verdicts are frozen.

## Threat model and trust assumptions

Adversarial **input**: untrusted text bytes, malformed/oversize files, partial publication, duplicated keys, out-of-order fields, embedded control characters, symlinks, nonregular files, hostile names, path substitution, stale generation, state-file corruption, time regressions. User-space single-process test harness is trusted, but there is **no trusted L2 identity or secret manager** in this milestone. Caller-provided claims of role, authorization, signature, user name, source path, or file ownership do **not** authenticate the proposal. A malicious same-UID writer, privileged file updater, compromised host, hostile storage, and reboot rollback are **outside provable security guarantees** here and must be documented.

**Never invent homegrown cryptography.** No production MAC/signature/authorization key, network endpoint, L2 daemon, privileged policy-application hook, or keystore is introduced. A future separate gate requires a selected established cryptographic/OS authorization mechanism, protected key lifecycle, monotonic replay storage and a plan to retire the unauthenticated legacy path. Until then `PRODUCTION_AUTHORIZATION: BLOCKED`.

## New offline canonical envelope

A versioned **ASCII LF-only**, fixed-order exact-key document (no comments/blank lines, CR, NUL, spaces, unknown/duplicate/missing keys), at most **4,096 bytes** and **10 lines**, in this exact sequence:

```text
HMI_L1_POLICY_PROPOSAL_V1
policy_schema_version=1
base_generation=0
generation=1
cpu_trigger_bp=3000
memory_trigger_bp=100
io_trigger_bp=500
confirmation_samples=3
END
```

The example contains **9 lines**, and the parser shall require exactly these 9 newline-terminated lines with `END\n` at EOF and no trailing bytes. The 10-line cap is merely defensive. Decimals are unsigned ASCII digits (no signs, no leading zeros except `0`), checked for overflow and typed ranges. `policy_schema_version=1` maps to `L1Policy.schema_version`; the `base_generation` is a compare-and-swap expectation for the **test-supplied** current core generation; `generation` must be strictly greater than base and current (no equal, rollback, overflow). Policy thresholds/confirmations must pass the unchanged compiled `l1_policy_valid()`. A CRC/hash, if used for byte-integrity tests, must never be presented as authentication; prefer strict byte parsing and no unnecessary cryptographic-looking field.

For file access, the test utility should accept only an explicit finite absolute Debian guest path, reject `..` segments, symlinks, nonregular files, oversized paths/files, and unexpected file mutation between read and validation. Read with bounded descriptors and close on failure. Do not rely on inode/mtime, `O_NOFOLLOW`, or ownership as a cryptographic guarantee; they are best-effort local safeguards. Only the private, disposable test environment may create fixtures. No input mutation or retained private data.

## New APIs and test-only authorization seam

- Pure, bounded `l1_proposal_parse(const uint8_t* buf, size_t len, L1Policy*, uint32_t* base, ...)` or equivalent; **no state changes**.
- `l1_proposal_check(const L1Core* current, ...)` verifies unchanged L1 compiled safety and base-generation expectation; never accepts a mere `authorized=1` field.
- Optional in-process test shim with **compile-time `L1_TESTING`** that injects a mock verifier whose positive verdict is bound to the **exact canonical proposal bytes**. The verifier is trusted only by a test harness; production compilation has no positive verifier provider and defaults to DENY. Document precisely why the mock cannot be a future production trust anchor.
- Compare-and-swap on a copied disposable `L1Core`; accepted test-only proposals can run `l1_apply_policy()` on that clone to prove HOLD reset and rollback ordering. **Never apply to a production/live L1 instance or persist policy from this test utility.**
- Expose clear rejection reasons: malformed envelope, unsupported schema, out-of-bounds behavior memory, stale/mismatched base generation, denied/unavailable authorization, tampered input, resource bound, and safe fallback.
- CLI, if created, is `l1_proposal_check` for *offline validity only*. It must explicitly print `authority=none production_apply=blocked` and may never acquire authority through `--authorize`, environment variable, source label or self-authored sidecar. Prefer no new runtime commands other than the bounded test tool.
- No API change to `l1_core.c`, `l1_shadow.c`, `l1_state.c`, the existing policy text parser or `l1_main` is authorized by this frozen V1.1 scope; tests document the legacy bypass as a separate future production blocker. If the threat model reveals a hard requirement to change legacy runtime, report it as a future gate rather than silently widening V1.1.

## Negative and acceptance corpus

At minimum, tests cover:
1. Exact canonical default-like generation-1 proposal; distinct valid future generations, safety extremes, boundary thresholds and confirmation bounds.
2. Duplicate/unknown/reordered/missing keys, trailing extra line/byte, CRLF, NUL, whitespace, wrong version/magic, overly long line/whole file, zero/overflow/negative decimal, sign, leading zero.
3. Equal/stale/replayed generation, wrong base generation, `UINT32_MAX` edge, rollback attempts, concurrent replacement, malicious symlink, directory/device input; each denial must leave copied L1 core **byte-for-byte identical**.
4. Mock verifier absent, verifier explicitly rejects, byte mutation after authorization, self-declared `authorized=true` and fabricated source label—none may produce an authoritative application. Test shim (when present) is clearly `test-only`.
5. Candidate accepted on a **test-only clone** goes from an active advisory action to HOLD with fresh confirmation, unchanged priority, bounded state, generation monotonicity and rollback semantics. Memory/I/O safety/fallback regressions are blockers.
6. State-load corruption and V1-to-V2 migration still pass; unchanged V2 72-byte persistence, shadow separation and historical V0.4–V1.0 checksums and GO/NO-GO.

## Measured budgets and decisions

Strict C11 -O2 optimized Debian QEMU executable with `-Wall -Wextra -Werror -Wpedantic`; `NDEBUG`, ASan, UBSan and leaks for correctness. All numeric parsing is overflow-safe; max 4 KiB envelope; no unbounded input/output, detached threads, network or services; no dynamic allocation in L1 decision path. Offline verifier RSS **<=8,192 KiB** at peak for bounded full-size valid/negative input, five optimized repetitions, and report median/min/max process CPU (no fabricated hard CPU budget). CI uses fast synthetic fixture smoke.

`PROPOSAL_VALIDATION: GO` only if canonical parsing, state-isolation, mock deny/verify-boundary, explicit blocked production status, safety checks, bounded file handling, normal/NDEBUG/sanitizer, and all historical identities pass. Otherwise `PROPOSAL_VALIDATION: NO_GO`. Independently and necessarily `PRODUCTION_AUTHORIZATION: BLOCKED`; `L2_DEPLOYMENT: NOT_AUTHORIZED`, `REAL_RESOURCE_BENEFIT: NOT_ESTABLISHED`, `ADAPTATION: NO_GO`, `ACTION_COUPLING: NO_GO`, `FORECAST_TRANSFER: UNDETERMINED`.
