## 1. Research question, separate from old performance goal

Primary R2 hypothesis: Given identical starting parameters but **different nonpersonal machine-condition histories**, a bounded perception layer can acquire **different calibrated operational expectations** and give more useful, truthful, uncertainty-aware machine-condition reports on independent held-out probe sequences than a static no-memory comparator, **without modifying existing safety actions or degrading measured operating constraints**.

"Personalized" here means operational specialization to a device's past conditions, **not** human identity, user intention, learned application semantics or simulated personality. Distinct states alone are not a success: random drift or overfitting can also make two machines different. Predictive / anomaly utility must survive independent evaluation against a capable fixed baseline and normal-vs-anomalous ground-truth classes.

The previous hypothetical goal "save more device resources than all layers consume" remains an unproven possible benefit, not the principal objective or an excuse to activate controls. **Nonregression** of safety, responsiveness, overhead and user autonomy is the binding constraint. OS-level effectiveness, L2+L3 total overhead and actual experience-driven machine individuality remain *undemonstrated* until measured in future separately authorized stages.

## 3. Mandatory separation of authority

- **Protected reflex lane:** `l1_step_at()` alone produces `HOLD | PREFER_INTERACTIVE | PROTECT_MEMORY | DEFER_IO`; this remains the only published advisory action source.
- **New perception lane:** receives validated **copies** of read-only observations and monotonic sampling metadata; produces optional *typed observational classifications/anomaly candidates*; **may not update** `L1Core`, `L1Shadow`, policy, action, previous-policy, persistence V1/V2 or a resource-control surface.
- **L1 → L2 candidate channel:** strictly a *versioned, test-only, bounded informational report*; no L2 is implemented or enabled. No remote connection or network protocol. Any future L2 policy proposal must go through a separately authenticated, reviewable boundary; no production authenticator exists.
- **L2 / L3 future:** L2 may contextualize events with apps/workflows and implement *separately approved* user actions; L3 may maintain persona, preferences and independent initiative. Neither can bypass L1 safety limits or push arbitrary logic into L1.

## 4. Input and output semantics

Inputs initially only from **synthetic, deterministic** copies of current Linux PSI-derived scalar observations:
- CPU `some avg10`, memory `full avg10`, I/O `full avg10` in integer basis points `0..10000`; explicit validity; monotonic sample time; optionally read-only cumulative PSI totals *only if frozen as separate optional fields in R2.1*.
- No application/window/process names, file contents, keystrokes, screenshots, private text, microphones, identifiers, user work history or Windows host telemetry.
- A high CPU PSI value is a stall-pressure signal, not a measurement of utilization, causation, performance benefit or badness; pressure pattern ≠ cause or app identity.

Output types must retain distinguishable namespaces:
`REFLEX_ACTION` (legacy core, unchanged), `PERCEPTION_STATE` (descriptive), `NOVELTY_SIGNAL` (candidate surprise relative to learned operational norm), `QUALITY_STATUS` (OK/WARMING_UP/STALE/INVALID/RESET), `EVIDENCE_SUMMARY` (counts/age/reference baseline version). Do not invent calibrated probability or "confidence" if no calibration exists. Non-learning state classification may use `QUIET, CPU_PRESSURE, MEMORY_PRESSURE, IO_PRESSURE, MIXED_PRESSURE, UNRELIABLE` as candidate vocabulary, finalized with exact thresholds and ambiguity rules *before any R2.1 test results*.

Cold-start, insufficient support, missing sensors, invalid timestamp or stale samples must **abstain from personalized anomaly claims**. `UNKNOWN` is preferable to falsely saying normal/anomalous. Legacy reflex MUST retain its own HOLD fallback rules. Report must always expose which channel originated a signal.

## 5. Bounded new memory, updates and persistence

- New perception state lives **beside** legacy core/learner, never embedded in `L1Core` or retrofitted into the 72-byte V2 state.
- Design ceiling for future `L1Perception` in-memory state: **512 bytes**, statically allocated / stack-local, no heap allocations on per-sample path. This is an acceptance ceiling, not a claim that an implementation already meets it.
- Store fixed-size, integer or bounded fixed-point aggregates, counts, timestamps, calibration and state version. Saturate arithmetic, validate overflow and reject impossible inputs. No raw event-history log in the core.
- New persistence, if later needed, is explicit and independent (e.g. V1 **perception** record with magic/version/length/checksum); CRC is only corruption detection, **not authentication**. Version mismatch, truncation, rollback, implausible counters, corrupt checksum or unavailable file must **reset perception to WARMING_UP**; leave protected core unchanged.
- No baseline poisoning via invalid samples. No rapid oscillation, adaptive runaway or permanent attachment to stale norms. New memories must support cold-start, bounded rate of change, reset and change-of-regime recovery.
- The future learning algorithm and precise memory fields remain a design choice to be documented **before** R2.2 implementation. Do not claim capacity or accuracy from a drawn diagram.

## 6. Frozen experimental design (for future R2.1–R2.3; not executed in R2.0)

**Two systems, same initial configuration:** A ("developer-like pressure rhythm") and B ("creative-like pressure rhythm") are *synthetic machine workload styles*, never guessed user occupations. Their histories differ; protected reflex configuration is identical. A and B experience their own training histories and identical shared diagnostic probes. New baseline states may differ on the same safe observation; action / safety outputs MUST NOT differ because of perception.

**Fixed corpus families:** quiet/stable, sustained CPU pressure, intermittent CPU bursts, sustained memory pressure, sustained I/O stalls, overlap, abrupt genuine regime change, slow drift, transient spike, recovery, invalid/missing input, decreasing monotonic time, counter resets, sparse/underpopulated history. Synthetic source ground truth is **an engineered label**, not ground truth for natural human machine behavior.

**Splits** per synthetic machine: 40 deterministic sessions; first 24 training / next 8 calibration / last 8 untouched held-out sessions. Sessions remain ordered in time and **must not share generated row identifiers across splits**. Shared diagnostic probes are disjoint from all three and may be repeated deterministically after full state resets. Minimum 256 samples per session, >=20 normal and >=20 positive anomaly *scoring windows per machine* on held-out after excluding bad/ambiguous samples; otherwise `R2_UTILITY: INSUFFICIENT_SUPPORT`. Require separate event-class counts and exclusion reasons; do not pool adjacent correlated samples as if independent statistical events.

**Preset generator seeds** (fixed now): A train=1101, calibration=1201, heldout=1301; B train=2101, calibration=2201, heldout=2301; shared probe=9001; regime-swap=9002; fault corpus=9003. A future deterministic stdlib-only corpus generator and exact per-split SHA-256 manifests must be committed **before implementing R2.2 adaptive memory**, with committed checksums and reviewed in their own commit; until then this is a preregistration of roles/seeds, not existing fixtures. The R2.1 non-learning classifier may be implemented after exact mapping is frozen; classify-only test outputs cannot retroactively set R2.2 scoring thresholds.

**Fixed comparators:** (1) always-`UNKNOWN` abstaining integrity control; (2) pre-declared no-memory global-threshold novelty/reference classifier selected on training/calibration only; (3) optionally a tuned fixed-per-class baseline whose tuning is restricted to calibration; its rule and exact thresholds must be published *before* held-out labels are inspected. Same feature budget and observation cadence as learner. A global fixed comparator is not to be intentionally crippled; if it is, mark comparison invalid.

**Primary held-out metric:** for each machine, compare (a) false-alert proportion on normal scoring windows and (b) sensitivity on engineered anomaly windows at calibration-fixed decision criterion. Require learner false-alert proportion **no greater than the strongest tuned fixed comparator** on *either* machine, learner sensitivity **no lower** on *either* machine, and strictly higher sensitivity on at least one preregistered anomaly family with >=5 independent positive events. All class-specific comparisons, abstention/coverage, misses and harmful false reassurance must be shown; no silent exclusion. With insufficient distinct events, result remains `UNDETERMINED`, never GO.

**Individuality/transfer test:** compare independent A/B learned snapshots after both have adequate support. Their bounded memory must differ for an explained, reproducible reason; there must be **at least two** preregistered shared-probe scenarios where different novelty classifications are *appropriate under the respective synthetic reference labels*, while neutral no-pressure/fault probes maintain matching safe outputs. Confirm byte-for-byte determinism for identical histories and checkpointed restart, and appropriately changing classifications after regime-swap 9002 without changing legacy reflex. Divergence without utility is **FAIL**, not "machine individuality" success.

**Statistical honesty:** observational patterns and anomaly labels are engineered, not externally validated. Aggregate percentages alone are inadequate; retain per-class confusion tables, exact independent episode counts, false negatives, false positives, abstentions, worst-case and per-machine breakdown. Avoid claims of natural-language understanding, causal optimization, humanlike individuality, energy savings or real-world anomaly accuracy.

## 7. Hard safety, footprint and determinism gates

On every future implementation commit:
1. Protected `L1Core` byte-by-byte, action-by-action equivalence with perception disabled for every test row, including invalid/regressed time and repeated recovery.
2. Existing RC0 normal, `NDEBUG`, ASan/UBSan/leak, replay, persistence, policy proposal, security, frozen historical evaluations and **all existing per-component frozen optimized budgets** pass unchanged. No updating old checksums to accept changed behavior.
3. Future perception payload + in-memory model <=512 bytes; bounded computational work (no unbounded scan/heap allocation per sample). Prospective optimized incremental perception step **median <= 1000 ns/sample and p95 <= 5000 ns/sample**, measured over >=5 batches of >=10,000 synthetic samples in isolated Debian QEMU; report CPU measurement method and normal baseline. These are proposed R2 study budgets, not RC0 measurements. Whole new observer/reporting process optimized RSS <=8192 KiB (and do not change any existing separate component budget). Benchmark regressions do not turn into safe GO.
4. Strict finite I/O limits and offline by default. No access to procfs beyond prior read-only paths, no kernel/host writes, no pressure generation, no cgroup/scheduler/firmware/machine actuator, no network service or uncontrolled persistent background agent.
5. Event messages are bounded, parseable, versioned, contain no private path/raw trace and cannot be mistaken for commands to alter OS settings.
6. If a new feature fails safety or nonregression on the shared tests, **R2_ENGINEERING: NO_GO** regardless of increased apparent personalization.
