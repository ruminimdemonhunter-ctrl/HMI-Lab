# HMI L2 V0.2 — Adaptive OS memory utility research architecture

**DOCUMENTATION-ONLY DESIGN. NO NEW L2 EXECUTABLE, DATASET, LIVE SENSOR, HELDOUT SCORING OR OS ADAPTATION IS AUTHORIZED HERE.**

Research track: [issue #37](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/37). Accepted technical baseline: L2 V0.1 merged [PR #36](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/pull/36), `main` merge `15ab2b9011dc3cfd25e1869c2c2891a593619a7d`. It uses pure fixed C11 state (840B), 4 opaque workspaces, 16 association nodes, 32 edges, 16 ordered triples, session-level updates, fixed decay, safe enum-only workspace candidate output. V0.1 is engineering GO and **synthetic-only history divergence**, not proved useful personalization.

## 1. The specific research question

Can a computer's bounded accumulated operational experience make a **more appropriate virtual-workspace choice for an upcoming simulated task** than a strong alternative that does not preserve long-term workspace relationships?

This question is more demanding than proving two computers produce different output strings. The correct future activity must be defined **independently of all prediction algorithms**, or the demonstration becomes circular. An apparently personalized output is not necessarily appropriate, safe, or wanted.

V0.2 evaluates **work-role sequences and text-only virtual workspace hints**, not actual folder layouts, software actions, user productivity, psychological preferences, hardware savings or L3 intelligence.

## 2. Architecture: two separate truth and prediction paths

```text
  independent scenario/world generator (future)
  latent upcoming role sequence + regime + available context
              |                    |
      HIDDEN OUTCOME TRUTH     allowed pre-query events ONLY
              |                    |
              |          +---------+---------------------+
              |          |         |         |           |
              |      L2 V0.1    RECENT    STATIC       NONE
              |      frozen     WINDOW    TEMPLATE    baseline
              |          |         |         |           |
              |          +---------+---------+-----------+
              |                    |
              |               enum-only hints
              |                    |
              +----> sealed deterministic scorer
                                   |
                       paired episode performance
                          by device/regime/mode
```

- **Simulator** contains latent simulated next-task/triple and exogenous environment constraints; it outputs two separate artifacts: available pre-query history/observation, and hidden future *outcome* truth. It must not choose the outcome by calling the L2 model or its baselines. Do not give label/profession/next-role to any candidate as an input.
- **Gatekeeper** checks canonical v1 event schema, eligible completed sessions, reset/gaps, fresh context, exact query identities, independence of episodes and identical allowed inputs for every candidate. It handles realistic limitations (observation ambiguity, multiple plausible next steps, regime switch, insufficient evidence).
- **Experimental runners** replay the same history and query into competing candidates with isolated state and identical permissions/freshness. V0.1 acts as an **unchanged, frozen benchmark**, not silently altered after results.
- **Outcome evaluator** (different code path to generator/runner) scores proposals against the precommitted simulated next task and externally declared harm/effort costs. It must be blind to algorithm names and not modify model behavior, baselines, labels or thresholds.
- **Integrity lock** binds source bytes/commit, generator, simulator, independent verifier, source manifests, partition identity, entire tuning choices/comparator identities and scored-calibration digest. Strict verify before heldout opening; no allowed hidden file/URL/history path.
- **Audit** publishes independent episodes, excluded counts, rule failures, overrides and negative scientific outcomes. A structurally valid corpus can still be scientifically unusable if post-reset support is inadequate.

## 3. What we compare — fair, nontrivial baselines

All candidates must take exactly the same bounded history and emit one of `NONE`, `CANDIDATE(role1,role2,role3)`, or `BLOCKED` with a reason. CANDIDATE always remains **text only**, requires approval, and cannot be executed.

| Candidate | Description | Scope |
|---|---|---|
| **V0.1-FROZEN** | Exact accepted L2 V0.1 algorithm, including 16-session halving and triple-support | Historical engineering benchmark; no retuning |
| **RECENT-WINDOW** | Strong deterministic last-N eligible **complete sessions** triple scoring with same permitted role vocab, safety/freshness/quality and support rules | Tune N over a preregistered calibration grid; must compete fairly |
| **STATIC-DEFAULT** | One global frequent virtual role triple learned/calibrated only from allowed train/calibration, or a frozen reasonable template before exposure | Equal output vocabulary; cannot see hidden machine labels |
| **STATIC-PER-WORKSPACE** | Fixed frequency/rule mapping from allowed training data for each opaque workspace, without updates after initialization | Stronger than naive global static; same allowed available evidence |
| **NONE** | Always abstain on optional workspace suggestions, still returns protected BLOCKED on unsafe conditions | Tests intrusion penalty/coverage and noninferiority |
| **V0.2-HYPOTHESIS (optional, separate)** | A preregistered bounded extension to handle regime changes, multiple modes, feedback or decay | Not automatically assumed better than V0.1; independent candidate, separate version/CI |

Fairness means each algorithm's training/calibration regime, state size, permitted events, support gate and permission controls are explicit. If V0.2 receives feedback or labels unavailable to alternatives, either supply the same information to comparators or mark comparisons **information-asymmetric** and **do not claim causal memory superiority**. If the static benchmark is supervised, disclose the difference; don't quietly choose a weaker comparator.

## 4. No hidden occupation classification; explicit mode vs task

Device histories A/B should be examples, not a binary hard-coded artist/programmer label. Include:
- A device used mainly for CODE_EDIT/BUILD_TEST/DOC_VIEW, with occasional CANVAS mode.
- Another used mainly for REFERENCES/CANVAS/ASSET_GROUP/EXPORT, with occasional code.
- A single machine that alternates two workspaces/modes frequently.
- A device whose dominant mode **changes**; the correct next task may be unlike the old majority, revealing harmful inertia.
- Cold start, insufficient post-reset support, missing/contradictory context, indistinguishable permitted signals, long gaps, multiple equally plausible outcomes.
- Quiet versus CPU/memory/IO pressure and denied permission: candidates must abstain/block identically regardless of historical identity.

Given identical currently observable context and equal histories, different hidden plans may be impossible to distinguish. The correct scientific outcome can be **UNKNOWN** or a scored abstention; don't count guessed task intent as intelligence.

## 5. Utility model: task-conditioned, explicit and falsifiable

V0.1 candidate is a **three-role sequence**, not an executable workspace layout. The future scorer should evaluate the match to the next simulated *three task-relevant role slots*, with costs fixed prior to data access. Provisional outcome design:

- Role-triple exact match earns the highest benefit.
- A declared per-position mismatch incurs explicit task cost, with a larger risk cost for a proposal that is demonstrably incompatible with the upcoming task.
- `NONE` earns neutral or small cost and is **preferable to a harmful false suggestion**.
- `BLOCKED` on unsafe source/context must be correct and unpenalized for all; an actionable suggestion during resource-constrained/invalid/unauthorized context is a safety failure.
- Evaluate **net task-adjusted utility** with separate counts for correct useful suggestions, incorrect/intrusive suggestions, abstentions, context coverage, reversal/regime recovery and error-to-safe-abstain transitions. Do not hide harm behind an aggregate favorable score or unfairly penalize NONE.
- Independently score session/episode once: 100 synthetic rows from one contiguous simulated routine are not 100 independent examples. For repeated devices, bootstrap or uncertainty interval must respect episode/device grouping; never imply the sample size is independent users.

The weights, thresholds, minimum sample sizes, fairness constraints, hidden outcome grammar, failure exclusions and study statistical decision rule **must be frozen in the V0.2 executable study preregistration before code/data/heldout**, not selected from study outcomes. This blueprint cannot be passed off as that final lock.

## 6. Evidence gates and independent evaluation

**Gate 0 — SCIENTIFIC VALIDITY:** complete simulator assumptions, independent truth separation, post-exclusion valid episode count, at least two distinct device histories and a mixed/changing-mode regime, no secret model-based truth, sufficient supported outcomes after last reset, independent split/machine/truth verification and locked baseline/score choice.

**Gate 1 — INTEGRITY:** signed-free byte-integrity (SHA256, not authentication), deterministic generator replay, required source/tree identities, calibration lock SHA, no earlier heldout file-open attempts, tampered lock fails, honest recorded invalid variants, outputs reconciled across scorers.

**Gate 2 — SAFE BEHAVIOR:** all candidates produce NONE/BLOCKED on the required fresh/invalid/permission/resource conflict cases, L1 core/shadow/actions remain identical observer-on/off, no executable proposal/file path/shell/OS change.

**Gate 3 — BOUNDED ENGINEERING:** 100,000 synthetic events, same or stricter frozen memory/CPU/RSS budgets, reproducible session ageing/capacity/regime transitions, normal/NDEBUG/ASan/UBSan/leak, Debian QEMU RC0 and GitHub CI. Report per candidate overhead and data dimensions.

**Gate 4 — SCIENTIFIC UTILITY (future study only):** for each device and major regime, noninferiority on harmful suggestions versus strongest permitted comparator and abstain baseline; improvement versus **strongest calibrated alternative**, not weakest, under predeclared paired episode loss. Establish a nontrivial number of independent strict wins on a designated task family, with all selected false positives visible and adequate coverage. If any expected controls fail, label `INVALID` or `NO_GO` rather than retroactively tuning.

**Gate 5 — APPROPRIATE INDIVIDUALITY:** identical code/initial state, independently justified differently labeled future tasks for separate histories, appropriately different safe decisions, no unsafe differences on matched safety probes, and **utility advantage** against non-memory alternatives. Different internal bytes/output does not satisfy Gate 5 by itself.

Each gate has an independent status; a future synthetic scientific GO **must never imply real device benefit, real user productivity or OS action permission**.

## 7. What V0.2 may build later and why

An extension of the accepted V0.1 memory could model:
- **regime change:** explicit time/session decay or adaptive forgetting, without erasing useful minority workspace modes;
- **multi-mode continuity:** one device maintains multiple active associations (not one occupation label);
- **negative outcome learning:** simulated reject/undo observations influence candidate eligibility only after separately frozen typed provenance and bounded feedback logic;
- **context-aware abstention:** disagreement between histories and current safe context suppresses suggestions.

Any new memory feature must be an **independent, versioned candidate** tested against V0.1 and baselines on exactly the same permissible streams, with a new state budget and no OS execution. Introducing an outcome channel requires freezing feedback schema and equal-information baseline policy.

## 8. Stop / trust boundaries

Do not: move files or directories, scan actual folders, read process names/windows/keystrokes/network, collect live PSI, enable services/daemon, invoke resource scheduler/cgroups, write L1 policy, alter Windows host, fetch models, persist private user observations, add L3, assume implicit user approval, or couple automated proposals to actions.

Any future guest-only observation, real user study, virtual folder overlay or actuation must be a separately approved project with explicit retention and revocation. L2 V0.2 study results, even if strong, will remain synthetic evidence. Prior L1 R2.3/R2.3b INVALID, R2.3c PASS, adaptation/action-coupling NO_GO and production authorization blocked remain unchanged.

## 9. Research roadmap

1. **V0.2 blueprint** (this PR): architecture and prospective study constraints, no code.
2. **V0.2 harness preflight** (separate approved implementation stage): tiny fixtures, independent truth/parser, fully tested baseline/reference implementations, known-answer scoring and future corpus support simulation.
3. **V0.2 fully preregistered synthetic study** (new freeze/approval): final split sizes, score and thresholds, candidate algorithm identities, locked calibration, **first** heldout scoring and explicit GO/NO_GO/INVALID.
4. **V0.3 optional adaptive feature research**: only if scientific evidence justifies; otherwise revisit the model and hypotheses rather than assuming more memory is better.
