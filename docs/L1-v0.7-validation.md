# HMI Level 1 v0.7 workload-evidence validation

## Scientific outcome

**DIAGNOSTICS_NO_GO.** The synthetic streaming evaluator, independent schedule
generation, accounting, safety checks, and memory target passed. The bounded
Debian recorder also produced a valid private trace, but its measured capture
loop cost was **3,676,400 ns/valid sample**, above the frozen
**1,000,000 ns/valid sample** budget. The overall verdict is therefore NO-GO.

The synthetic result is useful diagnostic evidence, not a new learning result.
The unchanged V0.6 learner differed from the strong `2000/75/600` static
predictor on only 58 any-class issuance windows. It improved macro Brier by
0.002959 across whole schedules, while memory Brier and recall regressed
slightly. The live `800/40/150` starting point left much more room for threshold
movement: 552 any-class differences and a 0.059847 macro-Brier reduction. These
configurations are separate experiments; the live-default score does not
replace or reinterpret the historical V0.6 result.

The retained verdicts are:

```text
DIAGNOSTICS: NO_GO
SHADOW_PREDICTION: NO_GO
ACTION_COUPLING: NO_GO
```

The held-out executable itself printed `DIAGNOSTICS_GO` after its synthetic-only
gates passed. It cannot consume the separately measured live-recorder budget.
Because the frozen overall criterion includes that budget, the executable line
is a scoped synthetic-gate result, not the authoritative milestone verdict;
the recorder CPU failure makes the project-level result `DIAGNOSTICS_NO_GO`.

No result authorizes forecast/action coupling or resource actuation.

The live-default learner reduced false alarms substantially, but also increased
false negatives in every class. Its memory recall fell from 0.760135 to
0.689189. With the V0.6-trained thresholds, CPU and I/O Brier improved slightly,
but memory Brier rose from 0.101029 to 0.101411 and recall fell from 0.638514 to
0.628378. A favorable aggregate error score is not a safety or action-coupling
criterion.

Time from an update to the earliest scoreable changed forecast was 0 ms / one
evaluated window for all live-default classes. For the trained configuration it
was CPU 300,000 ms / six windows, memory 0 ms / one window, and I/O 420,000 ms /
eight windows. This confirms that an update alone is not proof of useful
behavior: many updates had no immediate material prediction effect.

## Limitations

- All scored event truth is synthetic. The five-sample PSI trace establishes
  recorder/parser provenance only and contains no causal or latent labels.
- Binary forecasts and non-overlapping 60-second windows are coarse; only 58
  any-class trained-threshold differences occurred across 2,743 issuances.
- The near-threshold family intentionally creates material-difference
  opportunities and dominates the trained-threshold aggregate improvement.
- Live-default improvements accompany class-specific recall regressions and
  must not be interpreted as safety improvement.
- Whole schedules are independent across seeds, but families still share the
  same generator design and parameter ranges.
- FNV-1a detects accidental corruption, not malicious modification or origin.
- Recorder CPU exceeded its preregistered budget on a very small capture;
  startup was excluded, but procfs parsing and scheduler/VM noise remain.
- `ru_maxrss` and nanosecond CPU measurements are VM-, compiler-, kernel-, and
  host-load-sensitive.
- No real workload benefit, counterfactual resource response, calibration
  transfer, forecast persistence, action coupling, or actuator was tested.

## Post-held-out final-review corrections

After review of commit `d3f1b1c8`, the recorder and parser received three
correctness fixes. These changes occurred after held-out scoring and do not
alter the frozen generator, seeds, learner, forecast configurations, metrics,
checksums, recorded measurements, or NO-GO conclusions.

1. Publication now uses same-directory Linux `link()` creation followed by
   removal of the temporary name. Because link creation fails with `EEXIST`, a
   destination created after recording starts is never replaced. A synchronized
   regression creates a sentinel destination while the recorder is sleeping,
   verifies nonzero recorder exit, verifies the sentinel checksum is unchanged,
   and verifies temporary-file cleanup.
2. Unsigned decimal parsing checks `digit > maximum` before subtracting the
   digit, eliminating unsigned underflow. Properly checksummed fixtures prove
   `valid=2` and `flags=4` are rejected, while schema-valid flag combinations
   through mask value 3 remain accepted.
3. Duration mode writes the first sample whose relative monotonic timestamp is
   at or beyond the declared boundary before stopping. Checksummed deterministic
   fixtures accept 2,000 and 2,001 ms endpoints, reject 1,999 ms, and retain the
   exact-count rule for sample-limited captures. A live two-second Debian
   duration capture and an unchanged three-sample capture both pass the strict
   parser.

Normal, `NDEBUG`, ASan, UBSan, leak, persistence/migration, historical replay,
V0.4-V0.6 evaluation, and V0.7 normal/sanitizer diagnostic suites were repeated
in Debian QEMU. The V0.7 identities remained exactly:
