# HMI Level 1 v0.7 frozen workload-evidence and diagnostics protocol

Status: **frozen before implementation and before any V0.7 held-out run**.  
Issue: [#9](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/9).

V0.7 is an instrumentation, provenance, and experimental-quality milestone.
It does not introduce or tune a learning algorithm. The V0.6 learner,
`l1_step_at()` behavior, compiled priority, fallback rules, policy bounds, and
72-byte V2 state encoding are immutable. V0.4, V0.5, and V0.6 results and
checksums remain historical scientific records and retain their NO-GO
conclusions.

Any post-freeze change to this document's V0.7 held-out seeds, generator
distributions, trace schema, thresholds, diagnostic definitions, resource
budgets, or decision criteria invalidates the V0.7 held-out result and requires
a new preregistered evaluation version. Defect fixes that do not alter those
items must be identified before a replacement run.

## Questions and evidence tracks

The questions are whether L1 receives enough causally valid future evidence,
whether learned offsets become eligible to affect forecasts, whether they
actually affect forecasts, and where evaluator memory is spent. A threshold
update with no later scoreable forecast difference is not behavioral
improvement.

Two evidence tracks remain distinct:

1. **New controlled synthetic diagnostics.** New seeded scenarios vary latent
   event schedules as well as noise. Offline latent truth is used only for
   scoring and provenance. Runtime feedback remains cumulative-counter deltas.
2. **Read-only Debian PSI capture.** A user explicitly invokes a bounded local
   recorder. A real trace has no latent event truth and supports observational
   forecast/outcome diagnostics only. It cannot support causal resource-benefit
   or action-quality claims.

Neither track modifies V0.6 historical evaluations. No result authorizes
forecast/action coupling or resource actuation.

## Immutable forecast configurations

Every V0.7 diagnostic reports these configurations by name and value:

- `live-default`: CPU/memory/I/O forecast thresholds `800/40/150` bp;
- `v06-trained`: CPU/memory/I/O forecast thresholds `2000/75/600` bp.

For each configuration, compare the unchanged V0.6 outcome-aware learner with
the static predictor initialized from the same thresholds. Scores from one
configuration may never be attributed to the other. There is no threshold
search, training, or selection in V0.7.

The forecast horizon remains 60,000 ms, the eligible endpoint interval remains
60,000..65,000 ms inclusive, and an inter-sample gap above 5,000 ms invalidates
pending feedback. Outcome thresholds remain CPU `some` 800 bp, memory `full`
40 bp, and I/O `full` 150 bp over cumulative PSI microsecond deltas. Offset
steps, bounds, gates, error counts, reset semantics, and all other learner
constants remain exactly those in V0.6.

## Track A: independent synthetic scenarios

### Deterministic streams

PCG-XSH-RR 32 with 64-bit state/stream and SplitMix64 seed derivation supplies
four independent streams per `(seed, family)`:

- truth schedule: class, start, duration, overlap, and regime boundaries;
- observation noise and false spikes;
- cumulative-outcome rate noise;
- timing/fault injection.

The truth stream must be materially consumed for every event-bearing family.
Event schedules are generated before samples and remain inside family bounds.
The schedule fingerprint is FNV-1a-64 over only family ID, event class, start,
duration, regime boundaries, and fault positions—not observations or outcome
noise. Every event-bearing family must have a distinct schedule fingerprint for
every seed in a split. Idle is exempt because it has no event schedule.

All arithmetic is integer, values clamp to `0..10000` bp, and cumulative totals
are saturating unsigned 64-bit microseconds. The generator emits samples in
order to a streaming aggregator; it does not retain whole splits.

### Families

Nominal cadence is 1,000 ms. Bounds below are normative; exact integer draws
and distributions are frozen in the implementation commit before held-out is
enabled.

| ID | Family | Samples | Truth/fault requirements |
|---:|---|---:|---|
| 0 | idle | 1,200 | no latent event; ordinary observation/outcome noise |
| 1 | short-bursts | 2,400 | 12 truth-selected CPU/memory/I/O bursts, duration 2..25 samples |
| 2 | sustained-cpu | 3,000 | six CPU events, duration 80..240, randomized quiet gaps |
| 3 | sustained-memory | 3,000 | six memory events, duration 20..180, randomized quiet gaps |
| 4 | sustained-io | 3,000 | six I/O events, duration 30..220, randomized quiet gaps |
| 5 | transitions-overlap | 3,600 | truth-selected overlaps and memory > I/O > CPU transitions |
| 6 | long-regime-shifts | 4,800 | three randomized regime boundaries and long class regimes |
| 7 | near-threshold-learning | 5,400 | repeated truth events and near-threshold observations long enough for multiple gates |
| 8 | invalid-and-gaps | 3,000 | truth events plus seeded invalid blocks and 6..12-second gaps |
| 9 | regression-reset-corruption | 3,000 | truth events plus timestamp regressions, counter resets, and impossible deltas |

Inactive nominal observations are CPU/memory/I/O `600/10/50` bp. Active
nominals are CPU 3,600 bp, memory 180 bp, and I/O 750 bp. Ordinary uniform
observation noise is CPU `[-400,+400]`, memory `[-30,+30]`, and I/O
`[-120,+120]`. The near-threshold family alternates seeded regimes centered
within one V0.6 offset step of each tested base threshold so changed-forecast
opportunities can be diagnosed without changing learner logic.

Counter rates derive from latent truth plus independent bounded outcome noise;
they never derive from the forecast. Offline truth never enters
`l1_shadow_step_at()` or its feedback.

## Track B: versioned real PSI trace

### Recorder invocation and caps

The recorder is an explicitly invoked, foreground, unprivileged program. It
requires an absolute `--output` path whose resolved parent is outside
`/home/lab/hmi/src`. It refuses an existing destination and writes no other
file except a mode-0600 same-directory temporary file, which is atomically
renamed only after a complete footer and file `fsync`. Interruption or failure
removes the temporary file and does not publish a valid trace.

Exactly one finite limit is mandatory:

- `--samples 2..86400`, or
- `--duration-sec 2..86400`.

`--cadence-ms` defaults to 1,000 and is restricted to `1000..60000`. The
compiled file cap is 16,777,216 bytes. There is no unlimited mode, background
mode, automatic stress, upload, or default output location. Research captures
longer than a smoke check require the user to select duration and guest-local
destination explicitly.

### Frozen trace format: `HMI_L1_PSI_TRACE_V1`

The file is strict ASCII with LF endings:

```text
HMI_L1_PSI_TRACE_V1
schema=1
units=relative_ms,basis_points,microseconds
cadence_ms=<1000..60000>
limit=<samples|duration>
limit_value=<bounded integer>
columns=relative_ms,cpu_some_bp,memory_full_bp,io_full_bp,cpu_some_total_us,memory_full_total_us,io_full_total_us,valid,flags
D,<relative_ms>,<cpu_bp>,<memory_bp>,<io_bp>,<cpu_total_us>,<memory_total_us>,<io_total_us>,<0|1>,<flags>
...
END,count=<decimal>,fnv1a64=<16 lowercase hex digits>
```

FNV-1a-64 covers every exact byte from the magic line through the last `D`
line, including LF, and excludes the footer. It is corruption detection, not
authentication. Data timestamps are relative to the recorder's first
`CLOCK_MONOTONIC` sample and must strictly increase. Basis points are
`0..10000`; totals are cumulative microseconds. `flags` is a decimal bit mask:
bit 0 read/parse failure, bit 1 cadence overrun. Unknown bits are invalid.
Invalid rows contain zero numeric PSI fields, `valid=0`, and bit 0 set.

The trace contains no wall time, hostname, username, UID, PID, command line,
process data, environment, IP address, absolute path, file content, credential,
or host identifier. Raw recordings are ignored by Git, never uploaded, and
remain under the user's disposal/review control.

### Strict validation and temporal analysis

The parser streams one bounded line at a time and rejects: wrong/duplicate/
missing headers, unsupported versions, CR or non-ASCII data, lines above 512
bytes, unknown columns/flags, partial or extra content, footer/count/checksum
mismatch, negative/signed/overflowing values, range/unit errors, zero/repeated/
regressing timestamps, impossible `valid/flags` combinations, decreasing
counters without an explicit invalid boundary, and files above the cap.

The deterministic negative corpus covers truncation at every structural
section, partial final writes, malformed schema/version, repeated and
regressing timestamps, variable/late gaps, unit/range errors, integer overflow,
counter resets, checksum mismatch, extra footer data, and traces too short to
complete a 60-second forecast.

A research-length trace, if explicitly supplied later, is analyzed as a time
series: first 60% development, then a 65-second embargo, then the remaining
test region. No parameter is fitted on either region in V0.7. A smoke trace
shorter than one horizon validates capture/parser provenance only and is
reported as ineligible for forecast scoring—not padded or assigned labels.

## Frozen learning diagnostics

For each evidence track, threshold configuration, class, family/segment, and
aggregate, stream and report:

1. observations, issued forecasts, evaluated forecasts, and unfinished;
2. missing feedback by invalid sample, excessive gap/late endpoint, timestamp
   regression, counter decrease/reset, impossible delta/overflow, and too-short
   trace;
3. feedback eligibility rate and elapsed-window minimum/mean/p95/maximum;
4. TP/TN/FP/FN, precision, recall, false-alarm rate, F1, binary Brier, and
   positive prevalence for static and outcome-aware predictors;
5. adaptive updates, per-class offset min/max, saturation attempts, learner
   resets, false-alarm evidence, and miss evidence;
6. forecast windows issued while an offset is nonzero;
7. observations lying strictly between the static and effective thresholds
   (`counterfactual boundary opportunities`);
8. actual prediction-mask disagreements at issuance, per class and any-class;
9. scoreable changed forecasts classified as improved, worsened, or unchanged
   correctness, with changed-only TP/TN/FP/FN contribution;
10. elapsed milliseconds and evaluated windows from each update to its first
    scoreable forecast difference, or explicit `none`;
11. compiled L1 action and full `L1Core` byte mismatches between an action-only
    stream and an identical stream accompanied by diagnostics;
12. schedule fingerprint and full emitted-stream checksum.

Accounting identities are hard checks. For example, issued forecasts must
equal evaluated plus all mutually exclusive discard reasons plus unfinished;
scoreable disagreements must equal improved plus worsened plus equal-
correctness disagreements. Undefined ratios are printed as unavailable.

Synthetic uncertainty uses whole independent schedules: learner-minus-static
macro-Brier mean, sample standard deviation, median, range, wins/losses/ties,
exact two-sided sign test excluding ties, and five seed aggregates. Samples or
noise replications are not treated as independent trials. Real traces report
temporal segments without synthetic truth, event detection, or causal labels.

## Streaming and resource accounting

V0.6's recorded optimized evaluator RSS failure remains **19,196 KiB versus
the frozen 16,384 KiB limit**. V0.7 does not rewrite that measurement.

The V0.7 evaluator must generate and aggregate one scenario sequentially and
retain no complete split, per-sample lead array, or per-controller trace copy.
It prints deterministic allocation accounting for generator state, scenario
schedule, parser buffer, diagnostic states, metric accumulators, and any other
explicit allocation. `ru_maxrss` remains process-wide and is reported
separately from `sizeof(L1Core)` and `sizeof(L1Shadow)`.

Optimized Debian budgets, measured without sanitizers, are:

- streaming V0.7 evaluator peak RSS at most 16,384 KiB;
- recorder peak RSS at most 8,192 KiB;
- `sizeof(L1Core)` unchanged from merged V0.6 and `sizeof(L1Shadow)` at most
  208 bytes (the V0.6 value);
- streaming evaluator median CPU at most 500,000 ns/sample across five full
  verification repetitions;
- recorder CPU at most 1,000,000 ns/valid sample, excluding sleep, across a
  bounded smoke capture;
- trace file at most 16,777,216 bytes and no line above 512 bytes;
- no dynamic allocation in `l1_step_at()` or `l1_shadow_step_at()`.

Sanitizer RSS/timing is validation evidence only and is not compared with
optimized budgets.

## DIAGNOSTICS_GO / NO-GO

`DIAGNOSTICS_GO` requires all of the following:

1. strict recorder/validator round trip, checksum, bounds, atomic publication,
   restrictive permissions, interruption cleanup, and negative corpus pass;
2. every event-bearing synthetic schedule fingerprint is unique across seeds,
   latent event start/duration differs across seeds, and all frozen split
   checksums match their pinned implementation identities;
3. aggregate synthetic feedback eligibility is at least 80%, every rejection
   reason and too-short real trace is accounted explicitly, and all accounting
   identities pass;
4. verification and held-out synthetic data together exercise at least one
   learner update, nonzero-offset forecast window, boundary opportunity, and
   scoreable actual disagreement for every class; no prediction improvement is
   required;
5. changed-forecast benefit/harm and time-to-first-material-difference are
   reported without offline truth entering runtime feedback;
6. zero published-action or `L1Core` byte mismatches, zero safety-fallback
   violations, exact 72-byte V2 encoding, and unchanged V1 migration;
7. V0.3–V0.6 normal, `NDEBUG`, sanitizer/leak, replay, parser, persistence,
   manifest, checksum, and historical held-out smoke tests pass;
8. optimized recorder/evaluator memory, CPU, storage, and line-size budgets
   pass, with V0.6's historical RSS failure still reported separately;
9. trace provenance clearly distinguishes synthetic, real smoke, and any later
   user-supplied research capture, with no raw capture committed or uploaded;
10. source/Git audit finds no L2/L3, actuator, PSI trigger registration,
    scheduler/cgroup/kernel/device/firmware/network-control interface,
    credential, VM image, recording, or compiled artifact.

Failure of any condition is `DIAGNOSTICS_NO_GO`. This verdict concerns whether
the evidence and diagnostics machinery is fit for further read-only research;
it is not prediction GO. V0.6 remains:

```text
SHADOW_PREDICTION: NO_GO
ACTION_COUPLING: NO_GO
```

The five-sample path is a provenance/parser smoke check, not a prolonged or
scoreable workload recording. Any longer real capture requires a separately
explicit duration and guest-local destination. CI runs bounded development and
verification diagnostics under normal and sanitizer builds; the full held-out
split is run once in Debian after implementation freeze.

The final report records protocol and implementation commits, split and
schedule checksums, exact commands, compiler/kernel, trace provenance,
diagnostics, resource accounting, benchmarks, all discrepancies and negative
findings, and an explicit `DIAGNOSTICS_GO` or `DIAGNOSTICS_NO_GO`. The feature
branch is pushed to an unmerged PR against `main` referencing Issue #9.

No phase adds L2/L3, an actuator, scheduler/cgroup control, PSI trigger write,
kernel/device/firmware access, privileged operation, host command, network
telemetry, upload, or hardware control.
