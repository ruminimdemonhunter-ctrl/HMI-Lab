# HMI Level 1 R2.3c preflight validation

## Scope and conclusion

R2.3c implements only the offline, test-only scientific preflight frozen at
`548307598a304bb00fccef5b8510a2b2321d0131`. It creates no V3 corpus, does
not score held-out novelty data, and does not add a runtime learner or action
path.

```
R2_3C_PREFLIGHT: PASS
R2_3C_ENGINEERING: PASS
R2_3_STUDY: INVALID (historical)
R2_3B_STUDY: INVALID (historical)
R2_UTILITY: UNDETERMINED
R2_INDIVIDUALITY: UNDETERMINED
ADAPTATION: NO_GO
ACTION_COUPLING: NO_GO
REAL_EVIDENCE: INSUFFICIENT
FORECAST_TRANSFER: UNDETERMINED
PRODUCTION_AUTHORIZATION: BLOCKED
L2_DEPLOYMENT: NOT_AUTHORIZED
V1_2_BENEFIT_EXPERIMENT: BLOCKED
REAL_RESOURCE_BENEFIT: NOT_ESTABLISHED
```

`PASS` means the preflight harness caught its fixed structural failures. It is
not evidence that novelty recognition is useful, individualized, or safe to
couple to an action.

## Discrepancies and limitations

- The first local historical assertion expected 366 accepted observations.
  Actual replay of the byte-verified source produced 365. The invented count
  was removed; the frozen required facts -- last reset around S22-R271,
  exactly three post-reset observed buckets, and unsupported final state --
  were preserved and strengthened with strict row-order checks.
- GNU `/usr/bin/time` is not installed in the guest. The bounded harness
  measurement therefore used Python's monotonic clock and child `rusage`.
- SHA-256 and the canonical lock fingerprint detect byte divergence but do
  not authenticate a producer or prevent replay.
- Tiny synthetic fixtures prove harness behavior only. There was no V3
  corpus, held-out novelty run, live PSI capture, workload generation, or
  real-resource-benefit evaluation.
- Process RSS is dominated by the executable/runtime and is reported
  separately from fixed C object sizes.
