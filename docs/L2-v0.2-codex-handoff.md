## The key question to answer **before implementing more memory**

> Does the existing L2 V0.1 learned workspace/routine memory predict an appropriate upcoming simulated workspace role sequence more often, or with lower harmful suggestion cost, than a competitive last-N-session or static-per-workspace strategy supplied with the same observations?

V0.1 has shown A/B experiences produce different learned triples. This is engineering divergence only. V0.2 research aims for a **falsifiable, outcome-conditioned advantage**. If strong recency wins, that is a useful result; do not conceal it or assume an expanded learner should automatically be built.

## Future stages after explicit approval

### Phase 0 — freeze a precise, executable experimental contract

Create a new separately reviewable study issue/branch or a locked dedicated phase PR as approved by the owner. BEFORE executable code or synthetic outcome corpus:
- Specify causal simulator structure, independent hidden next-task/outcome truth, allowed observation vs unavailable future label, noisy/ambiguous cases and source-of-truth generation path.
- Freeze episode boundaries, train/calibration/heldout split per device/regime, seed IDs, support/exclusion/independence minima, time-order embargo, and study stopping rules.
- Freeze **integer or rational loss/cost function** (benefit, mismatches, intrusive candidates, NONE, unsafe suggestion as hard gate), regime-change recovery, confidence/paired error metrics and minimum independently winning cases.
- Freeze exact strongest-recent baseline grid, static baselines, abstention reference, model/checkpoint state limitations, tie-breakers and fair equal-information rules.
- Freeze lock grammar and SHA256 verification for actual source, simulator, verifier, data, comparator parameters, calibration selections, test fixture identities and no heldout open before valid lock.
- Do **not** copy future truth targets from L2 V0.1's scored outputs. The simulator's expected result must be derivable without invoking L2 or any comparator.
- Include a documented "same visible context but different hidden intention" negative-control pair; outcomes cannot be magically distinguishable if input information is insufficient.

### Phase 1 — preflight BEFORE any large data freeze

Build tiny deterministic training-only fixtures, independent post-exclusion/session verifier and known-answer truth/scoring mock. Recompute eligibility and post-reset L2 support through the *actual* accepted engine, and baseline comparable paths. Stress input faults, non-independent duplicates and late resets. Inject old R2.3-like eligibility mismatch and R2.3b-like unsupported training reference to prove stop gates. Verify candidate-independent truth and reproduce zero heldout file-open calls on a deliberately broken lock.

If preflight fails, publish BLOCKED/INVALID and stop. Do not repair a frozen corpus in place.

### Phase 2 — new scientific corpus, baseline and calibration (requires separate sign-off)

Commit generator, independent truth verifier and prospective hash/identity manifest in strict prereg order. Keep entire episodes disjoint across train/calibrate/untouched heldout, not rows. Add context/mode transitions and a real recency-strength test; align information available to each comparator. Calibrate only predeclared settings. Strictly commit SHA-bound calibration lock *before* first heldout opening. No user/workstation files or live operating-system observations.

### Phase 3 — one honest heldout evaluation (requires separate owner authorization)

Run paired episode-level candidate comparisons. Produce per-device/regime utility, harmful/intrusive suggestions, abstention/coverage, mode-switch recovery and independent strict win events. Missing support, ineligible session, unsafe suggestion or lock mismatch must fail/stop as specified in the frozen protocol. Score independent truth under a scorer that cannot see candidate identity. Save full result, including unfavorable findings.

### Phase 4 — engineering qualification

All changes restricted to separate offline synthetic tooling/new `src/level2/` candidate files, no protected L1 or accepted V0.1 edits. Strict C11/normal/NDEBUG/sanitizers/leak, no heap blowup, bounded candidate state, 100,000-row finite replay, Debian QEMU CPU/RSS and historical RC0/104B core/208B shadow noninterference. GitHub CI exact-head evidence, full provenance and reproducible report. Keep PR draft/unmerged for independent review.
