# HMI L2 V0.2 — Scientific evaluation blueprint: is learned workspace memory useful?

**BLUEPRINT STAGE, NOT AN EXECUTED OR FULLY LOCKED HELDOUT STUDY.** Companion `docs/L2-v0.2-architecture.md` contains system components and safety/authority boundaries. Tracking [issue #37](https://github.com/ruminimdemonhunter-ctrl/HMI-Lab/issues/37). Accepted branch base: merged L2 V0.1 `15ab2b9011dc3cfd25e1869c2c2891a593619a7d`.

## 1. Registered hypothesis and falsifiability

Main hypothesis to *later* preregister with exact weights/split sizes: in simulated, recurring, changing OS workspace environments, the existing 840B L2 V0.1 session-level relationship memory or an explicitly separate revised bounded-memory candidate yields **lower cost per independent upcoming workspace session** than the strongest fair fixed/recent-session comparator **without increased harmful recommendations**. Histories A/B/MIXED are engineering examples; the actual study cannot be a repeat of those known-answer sequences with labels copied from model output.

Null outcome includes:
- simple recency or static per-workspace policy matches/exceeds the memory system;
- model is more different but no more correct;
- advantages occur only when unstable cases are excluded or labels leak to the model;
- model works only in dominant mode, loses on regime change, or produces unsafe/confident false suggestions;
- insufficient independent supported episodes after reset.

A scientific `NO_GO` is a valid result. Improper corpus, eligibility, truth or heldout order produces `INVALID`, not a favorable score.

## 2. Research comparisons and permitted inputs

All candidates consume identical allowed `HMI_L2_EVENT_V1` synthetic event streams (session boundaries, workspaces, role categories, quality, simulated context and pressure descriptors). All produce the same candidate triple/abstain/block enum format. No hidden future event/target label, occupation, machine ID as classification shortcut, app/file/user contents, cost function internals or human permission is available to runners.

Predeclare at least:
- `L2_V01_FROZEN`: exact merged state/decision semantics and source identity, untouched.
- `STRONG_RECENT_N`: eligible complete-session sliding history; role-triple counts and the strongest deterministic recency choice, with N selected on calibration *only*. State budget and safety/quality mask reported.
- `STATIC_WORKSPACE`: per-workspace/static trained template on **training only** (not oracle future labels), same candidate output.
- `STATIC_GLOBAL`: one global static trained template.
- `ALWAYS_NONE`: safe no-proposal reference; common BLOCKED conditions must still report BLOCKED.
- An optional new context/feedback/decay learner gets its **own independent ID and preregistered code**. It may not replace the frozen V0.1 entry and must be compared on matched inputs.

Use a strong baseline's best calibrated threshold/candidate choice as primary comparator. Do not select only static-global when recency wins. For fair comparisons, explicitly state whether a baseline has privileged supervised training; where information differs, report asymmetric status and don't call the outcome a controlled learner benefit.

## 3. Independent scenario generation / evaluation truth

Before any synthetic corpus exists, write down the scenario **causal state** (hidden requested next-workflow plan and mode transition probabilities) separately from what the offline engine is allowed to observe. Later code uses independent fixture generator/verifier paths, not a predictor-inferred target. Every session includes:
- a device/workspace opaque identifier and one independent episode ID;
- permitted time/quality/role observations prior to a query;
- a hidden independent upcoming task role triple or ambiguity flag;
- regime: steady, alternating, change-point, mixed, cold, post-reset/gap, unknown/contradictory;
- independent safety/permission state and a utility/effort assumption or explicit abstention ground truth.

No hidden truth may be copied into role observations except information naturally observable **before** the query. Distinct synthetic devices may use the same role vocab and same kinds of tasks; the output should evolve from different histories rather than a hard-coded device tag.

Test the generator with adversarial "same visible past, different hidden future" twins. These are intentional identification limits: appropriate safe uncertainty should not be scored as failure. Also verify that dummy candidates cannot trivially read fixture filenames/episode IDs/metadata unavailable to the actual model.

Use deterministic seeds split by device and regime. Entire independently generated sessions/episodes, not rows, are the unit of evaluation. Cloned windows, heavily overlapping context or repeated versions of the same episode are non-independent; detect and report them. Future frozen study must specify concrete counts, seeds, train/calibration/heldout boundaries, exclusion grammar, hashes, minimum supported count **per device and per family**, and stop conditions before using any heldout.

## 4. Outcome scoring design — finalize exact numerical loss before study implementation

Outcome is **not** a measured real filesystem operation. It is a simulated choice among three-role virtual layout hints:
- reward matches to the independently recorded next-task triple;
- count per-position mismatches and materially wrong context suggestions;
- separately count `CANDIDATE` under a forbidden/unsafe or no-consent condition as **critical safety failure**; it may not be compensated by wins on ordinary sessions;
- distinguish `NONE` for low support/ambiguous task versus unnecessary abstention on strong evidence;
- `BLOCKED` is correct on resource pressure/permission-denial and a false block on safe opportunity is a lost-coverage cost;
- penalize repeat intrusive or stale recommendations under regime change; include first useful recovery after shift.

Prior to generating/scoring *any* study heldout, publish exact fixed integer/rational task cost weights, role-match metric, result grammar, pairing rule, coverage denominator, ties, abstention penalty and exclusion list. Include always-NONE reference to prove gains aren't an artifact of penalizing abstention too highly. No free-text subjective scoring, retroactive cost weights or manual scoring discretion.

One episode contributes one primary scored decision. Show by-device and by-regime paired **loss, useful suggestions, wrong/intrusive suggestions, abstention, coverage, unsafe violation, and switch-recovery**. Nontrivial results need independent wins rather than exploiting millions of near-identical synthetic events.

## 5. Ordering and preregistration integrity

**Stage A — Blueprint (this PR):** docs-only, propose simulator, comparator and score contracts, no data generation, no L2 code change.

**Stage B — preflight harness (requires approval):** commit an exact new V0.2 **frozen executable-study protocol** with detailed schemas, named hypotheses, state sizes, baseline grids, loss weights, expected minimum population, seeds and threshold gates **before writing study algorithms or corpus**. Separately add tiny training-only known-answer fixtures with both supportive and unsupported reference streams (especially late reset / aging) and negative truth/eligibility controls. Verify actual V0.1 and baseline implementations can reach support. Verify no first-heldout-open happened; start with missing heldout path and rejected mock lock.

**Stage C — prospective corpus freeze:** independent source/truth generator and separate independent structural verifier, post-exclusion reconciliation, per-machine/regime support checks; commit seed/config/code plus immutable SHA256 manifest. Invalidity after freeze => INVALID and new corpus version; never correct the old V2/R2.3b precedent by silent rewrite.

**Stage D — calibration:** select only from declared grids with training/calibration partitions; lock actual SHA256 of all code/data/spec files and outputs, selected strongest comparator(s), complete tuning parameters and fixed utility metrics. Refuse malformed/duplicate/unknown fields and digest mismatch. **Locked before heldout first open**.

**Stage E — heldout:** date-scoped episode replay per device, source-identity and lock verification, paired best comparator scoring, separate blinded independent truth scorer. May run **only after a fresh explicit study authorization**. Expose any early stop, invalid eligibility, misuse or data leakage. Never run repeatedly to chase a pass; material change => new study version.

**Stage F — scientific verdict:** publish full case-level aggregate reconciliation without private data, by-regime comparison with uncertainties, exact source/manifest SHA, classification of INVALID / VALID_NO_GO / SCIENTIFIC_GO only per frozen decision rules. No change to action authority.

## 6. Proposed validity and outcome gates to freeze numerically later

Final science GO must satisfy **all**, not an aggregate sole criterion:
1. Corpus integrity, source/input identity, independent truth, disjoint partitions, supported pre-query memory after resets, calibrated strongest baseline and no premature heldout reading.
2. No unsafe CANDIDATE during denied/unsafe/invalid source conditions for **any** device. Protected L1 action/core/shadow bytes identical with L2 observation off/on and historical RC0 untouched.
3. Sufficient **independent scored episodes per device** in steady, mixed and regime-change contexts. Freeze minima before creating data; insufficient sample yields INSUFFICIENT/INVALID according to declared rule, not success.
4. No worse harmful or intrusive suggestion frequency for each device versus strongest relevant comparator and always-NONE reference, within a declared noninferiority tolerance (ideally exact zero for disallowed safety states). No hiding harm under averaged gains.
5. Lower paired loss than the *strongest* calibrated comparator for each device where support exists, with an explicit strict win count in an independently supported task family, and no catastrophic mode-switch regression.
6. Appropriate individuality requires *correctly* different recommendations under independently distinct future tasks for identical query/context, with identical safe behavior on shared negative controls. Difference alone is insufficient.

An honest null/no-go result or invalidity stays published. Do not label scientific GO on the initial engineering A/B fixtures.

## 7. Engineering and environment boundary

V0.2 documents shall not edit accepted V0.1 `L2State` (840B), its frozen corpus/manifest, tests or observed original benchmark. A future candidate must be separately named/versioned. No privileged reads/writes or production authorization. Target cheap, bounded C11 core and finite synthetic-only CLI; any budget changes must be prospective and independently approved. Maintain normal/NDEBUG/ASan/UBSan/leak, 100K+ synthetic event replay, exact L1 104B core / 208B shadow action/byte isolation, RC0 full and source audits, isolated Debian QEMU no host OS mutation.

Privacy: simulated role enums and opaque identifiers only. No process list, files/paths, window titles, keyboard/mouse behavior, real PSI/network, actual workspace changes, L2->L1 policy writes, daemon/telemetry, user profiling, L3 integration or real user feedback in this phase.
